## 목표

## 고칠 때

- 노트북은 빌더 글·spec을 고쳐 다시 빌드한다. 받은 원본 `code/`는 그대로 둔다. 고친 곳은 다시 실행해 확인한다.
- 흐름·구조를 바꾸는 큰 변경은 하지 않는다. 목록으로 남겨 사용자에게 묻는다.

## 배포 (단계마다)

1. 테스트 OK(`uv run --extra notebooks python -m unittest discover -s dev/tests -p 'test_*.py'`), 노트북 출력 없음, 키 없음.
2. 작업 트리를 깨끗하게 한다. 출력만 바뀐 노트북은 `git stash`한다(버리지 않는다). 고친 것은 `dev`에 커밋한다.
3. `git switch main && git merge dev && bash dev/release.sh v13`(2단계는 `v14`) → `git switch dev && git push origin study dev`. 로컬 `main`은 push하지 않는다.
4. 임시 폴더에 위 clone 명령으로 받고, `uv sync --extra notebooks` → `uv run python -m config.check --json` → 그날 LAB 하나와 과제 하나를 실행한다.
