그대로 말하기

"Agent는 스킬마다 이름과 설명 한 줄만 먼저 봅니다. 요청이 그 설명과 맞는다고 판단할 때만 파일을 열어 본문을 읽습니다. 그래서 설명 한 줄이 이 스킬을 쓸지 말지를 정합니다."

쉬운 설명

슬라이드 p17은 "Agent는 필요한 Skill을 선택하고 해당 절차를 따른다"까지만 말합니다. 어떻게 고르는지가 빠져 있습니다. 답은 세 단계로 나눠 읽는 방식입니다. 이를 progressive disclosure(단계적 공개)라고 부릅니다.

  • 1단계: 시작할 때 모든 스킬의 이름과 설명만 시스템 프롬프트에 들어갑니다. 책의 목차와 같습니다.
  • 2단계: 요청과 맞는 스킬이 있으면 Agent가 read_file로 SKILL.md 본문을 읽습니다. 해당 장을 펼치는 것과 같습니다.
  • 3단계: 본문이 가리키는 추가 파일이 있으면 그때 엽니다. 이 실습의 스킬에는 추가 파일이 없습니다.

스킬이 수십 개여도 본문을 한꺼번에 넣지 않으니 모델이 읽을 양(토큰)이 줄어듭니다. 대신 설명이 모호하면 Agent가 스킬을 열지 않습니다. LAB 4.1은 일부러 그 사고를 내 보는 실습입니다.

우리 Agent가 실제로 받는 글

4-1 LAB과 같은 설정으로 Agent를 만들고, 모델 자리에 받은 글을 기록만 하는 가짜 모델을 넣어 첫 호출의 시스템 프롬프트를 꺼냈습니다. 이 글은 모델이 아니라 deepagents가 만드므로 사내 모델에서도 같습니다. 디버그 셀을 켜면 강사 화면에서 이 부분을 보여 줄 수 있습니다.

코드 작성, 수학 계산 등 보고서·리서치 범위를 벗어난 요청은 정중히 거절한다.

확인한 것: 40이 실제로 끊는다

항상 도구만 부르는 가짜 모델로 LAB과 같은 Agent를 돌렸더니, 모델을 19번 부른 뒤 GraphRecursionError: Recursion limit of 40 reached without hitting a stop condition.로 멈췄습니다. 조용히 도는 대신 오류로 멈추는 것이 이 실습의 예외 처리입니다.

LAB 주석의 "기본값 25"는 LangGraph 일반 기본값(langchain-core DEFAULT_RECURSION_LIMIT = 25)입니다. create_deep_agent는 기본값을 9_999로 올려 두므로(B의 코드), 40을 넘기지 않으면 사실상 상한이 없습니다. 실행할 때 넘긴 40이 9,999를 덮어씁니다(langchain-core merge_configs).

Langfuse, Observability & Application Tracing

"The core of this is application tracing — structured logs of every request that capture the exact prompt sent, the model's response, token usage, latency, and any tools or retrieval steps in between."

핵심은 요청마다 남기는 구조화된 기록이다. 실제로 보낸 프롬프트, 모델의 답, 토큰, 걸린 시간, 중간의 도구·검색 단계가 담긴다.

같은 문서

Ftrace · observation · span · generation · score

LEC 1.3 · p6LEC 1.5 · p8LAB 2~4장LAB 5~8장
그대로 말하기

"trace는 요청 하나의 영수증입니다. 영수증의 줄 하나하나를 observation이라고 하고, 그중 모델을 부른 줄이 generation입니다. 토큰과 비용은 generation 줄에 적힙니다. span은 걸린 시간만 있는 일반 줄이고, score는 영수증에 붙이는 평가 점수입니다."

정의 (원문은 Langfuse 문서)
용어문서 원문쉬운 말4-2 LAB에서
trace"A trace represents a single request or operation, for example one chatbot interaction from the user's question to the final response."요청 하나의 전체 기록2장: invoke 한 번에 trace 하나
observation"Observations are the individual steps of your application: LLM calls, tool calls, retrieval steps, and so on. They can be nested to reflect the structure of your application"trace 안의 한 단계. 트리의 한 줄트리의 모든 줄
span"span is the generic observation type for durations of units of work in a trace."시작과 끝(걸린 시간)이 있는 일반 단계4장 @observe 함수(retrieve-documents 등)
generation"generation logs generations of AI models incl. prompts, token usage and costs"모델 호출 단계. 프롬프트·토큰·비용이 붙음ChatOpenAI 줄
score"Scores are Langfuse's universal data object for storing evaluation results."평가 결과. 이름·값을 trace에 붙임5~8장 create_score

출처: Observability Data Model(trace, observation), Observation Types(span, generation), Evaluation Core Concepts(score). 모두 글자 그대로.

슬라이드 p8은 @observe가 "Trace 또는 Span"을 만든다고 합니다. 헷갈리면 이 문장으로 정리합니다: "(Langfuse calls spans observations; span is also a specific observation type.)" 즉 span은 넓게는 단계 전체를, 좁게는 그중 한 종류를 가리킵니다(Data Model).

score는 "Every score has a name, a value, and a data type (NUMERIC, CATEGORICAL, BOOLEAN, or TEXT)."입니다(Core Concepts). LAB의 점수는 모두 숫자(0.0~1.0)입니다.

LAB 3장 trace에서 보일 모양
  • chainLangGraph trace 이름
    • agentagent 노드 이름에 agent가 있어 agent로 표시
      • generationChatOpenAI 토큰·시간
    • chaintools_condition 도구를 부를지 끝낼지
    • chaintools
      • toolget_weather 입력: 도시 이름
    • agentagent

단계 이름과 순서는 LAB 3.3 볼 지점에서, 종류 표시는 설치된 Langfuse SDK 4.15.4의 CallbackHandler 규칙(이 이름들로 함수를 직접 불러 확인)에서 옮겼습니다: 모델 호출 → generation, @tool → tool, 체인·노드 → chain(이름에 agent가 들어가면 agent), @observe 기본 → span. 화면의 실제 아이콘은 아침에 확인하세요.

G점수(Scores)는 화면 어디에 보이나

LEC 2.1 · p10LAB 첫 안내 "[Scores] 탭"LAB 5~8장
그대로 말하기

"점수는 두 곳에서 봅니다. trace 하나를 열면 그 기록에 붙은 점수가 보이고, 왼쪽 메뉴의 Scores에서는 모든 점수를 모아 봅니다. 코드 출력에 나오는 '[Scores] 탭'은 이 Scores 메뉴를 말합니다."

세 군데 (공식 문서 기준)
  • trace 안: trace를 열면 이름 옆에 점수 표시가 붙고, 오른쪽 자세히 보기 칸에 Scores 탭이 있습니다(아래 두 화면).
  • 목록에서 거르기: Tracing 검색 칸 예시에 scores.accuracy:>0.8가 있습니다. 점수로 trace를 거를 수 있다는 뜻입니다(위 F의 화면 맨 위).
  • Scores 메뉴: 모든 점수를 모아 보는 곳입니다. Analytics 탭에서 점수의 분포와 추이를 봅니다.

"Go to your project in Langfuse · Click on Scores in the navigation menu · Select the Analytics tab"

프로젝트를 열고, 메뉴에서 Scores를 누르고, Analytics 탭을 고른다.
