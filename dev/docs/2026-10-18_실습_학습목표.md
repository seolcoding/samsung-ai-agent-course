# 실습 학습 목표와 과제 구조 (2026-10-18 확정)

14차수부터 쓰는 실습 과제의 기준이다. 실습마다 학습 목표를 정하고, 과제는 **그 목표를 코드로 구현할 수 있는지** 확인한다. 목표 하나가 채점 기준 하나다.
목표는 교안 PDF와 원본 실습 코드를 실습마다 조사해 후보를 만들고(서브에이전트 병렬 조사), 강사가 실습별로 골랐다.

## 1. 구조

| | M1 (1·2일차) | M2 (3·4일차) |
|---|---|---|
| 방식 | **챗봇 트랙**: 장을 배울 때마다 같은 챗봇을 한 단계씩 키운다 | **실습별 독립 과제**: 챗봇과 다른 터미널 프로그램, 한 파일·한 명령 |
| 위치 | `course/Chapter01/tasks/<번호>_task.py` (챗봇 앱은 화면 코드가 파일 안에 있음, 2-2는 터미널) — 2026-10-19 폴더 없이 실습마다 파일 하나로 | `course/Chapter02/tasks/<번호>_task.py` |
| 실행 | `uv run --env-file .env python course/Chapter01/tasks/<번호>_task.py`(챗봇 앱은 python으로 실행하면 스스로 Streamlit을 띄운다) | `uv run --env-file .env python course/Chapter02/tasks/<번호>_task.py` |
| 확인 | 사이드바 "✅ 과제 확인" 버튼(과제 파일 안 확인 코드, 2026-10-19) | 실행 끝의 `✅ 확인`(과제 파일 안 확인 코드) |

공통 결정:
- 실습 노트북은 권마다 하나이고 이름은 `_LAB`이다. 옛 빈칸판은 빌드하지 않는다(git 이력에 남음). 같은 날 M1은 객관식을 빼고 값 바꾸기판(완성 코드 + CHANGE_HERE)으로 바꿨다(`dev/AGENTS.md` §1). M2는 객관식판이다.
- 프롬프트는 `✨` 핵심어만 준다(지시문 완성본은 주지 않는다). 판정은 과제 파일 안 확인 코드가 한다(LLM 채점·채점 스킬 없음, 2026-10-19).
- 과제는 30분 안에 끝나게 한다(2026-10-19): 채울 자리 2곳, 파일 80줄 안팎, 맨 위 안내 5줄(▶️ 실행·✅ 확인·🆘 막히면), 자리마다 `✍️` 한 줄·`✨` 핵심어 한 줄. 챗봇 앱은 이어 붙이지 않고 과제마다 그 실습 내용만 담는다(화면 코드는 파일 안에, 2-3은 화면을 직접 만든다). 판정은 파일 안 확인 코드가 한다(터미널은 실행 끝 `✅ 확인`, 챗봇은 사이드바 "✅ 과제 확인")..
- 2-2 Multi-Agent는 Streamlit에 억지로 넣지 않고 터미널 과제로 한다(시연 위주, 고객사 약속).

## 2. 실습별 학습 목표

### M1 — 챗봇 앱 과제(2-2만 터미널)

| 실습 | 형태 | 학습 목표 |
|---|---|---|
| **1-2 LLM API** | 챗봇 앱 | ① `requests`로 HTTP 요청을 직접 보내 LLM 답(`choices[0].message.content`)을 꺼낼 수 있다 ② LangChain(`get_llm()`)의 `stream()`으로 답을 조각 단위로 화면에 보여 줄 수 있다 |
| **1-3 LangChain** | 챗봇 앱 | ① `prompt \| llm \| StrOutputParser()` LCEL 체인으로 답할 수 있다 ② `MessagesPlaceholder("history")`에 앞 대화를 넣어 기억하게 할 수 있다 |
| **1-4 RAG** | 챗봇 앱 | ① 검색한 약관 청크를 context로 넣어 답할 수 있다 ② 문서에 없는 질문에는 "문서에서 확인할 수 없습니다"라고 답하게 할 수 있다 |
| **2-1 LangGraph** | 챗봇 앱 | ① agent 노드와 `ToolNode`를 conditional edge로 이은 그래프를 만들 수 있다 ② `MemorySaver`와 `thread_id`로 대화 기억을 그래프에 맡길 수 있다 |
| **2-2 Multi-Agent** | 터미널 과제 | ① Researcher와 Writer 두 노드를 만들고 `research_result`·`draft` 키로 결과를 넘길 수 있다 ② Researcher에게만 검색 도구를 줘 `Tool Message`가 Researcher 단계에만 나오게 할 수 있다 |
| **2-3 Streamlit** | Streamlit 앱(화면을 직접 만듦) | ① `st.session_state`에 대화 기록을 남겨, 질문할 때마다 파일이 다시 실행되어도 지난 대화가 화면에 남게 할 수 있다 ② `st.write_stream`으로 RAG 체인의 답을 조각 단위로 그리고, 다 붙은 답을 대화 기록에 남길 수 있다 |

### M2 — 실습별 독립 과제

| 실습 | 학습 목표 |
|---|---|
| **3-1 복습** | ① 검색기를 `@tool search_policy`로 감싸 약관 검색 도구를 만들 수 있다 ② `tools_condition`과 `add_edge("tools","agent")`로 도구를 반복해 부르는 그래프를 만들 수 있다 |
| **3-2 MCP** | ① FastMCP `@mcp.tool()`로 함수 2개를 MCP 도구로 등록할 수 있다 ② 받은 MCP 도구를 LangGraph Agent에 붙여 질문에 도구로 답하게 할 수 있다 |
| **3-3 A2A** | ① `t.AgentCard`와 `t.AgentSkill`로 Agent Card를 만들 수 있다 ② `A2ACardResolver`로 카드를 읽고 메시지를 보내 응답 텍스트를 출력할 수 있다 |
| **3-4 LangGraph 심화** | ① `MemorySaver`와 `thread_id`로 같은 thread는 이어 가고 다른 thread는 모르는 것을 `get_state` 메시지 수로 보일 수 있다 ② `InMemoryStore` namespace에 사용자 정보를 `put`하고 새 thread에서 `search`로 꺼내 쓸 수 있다 |
| **4-1 Harness** | ① `create_deep_agent`에 모델·도구·작업 공간·skills 폴더를 묶어 Deep Agent를 만들 수 있다 ② 머리말(`name`·`description`)과 양식 본문이 있는 SKILL.md를 써서 Agent가 그 양식대로 답하게 할 수 있다 |
| **4-2 관측** | ① `CallbackHandler`를 config로 넘겨 체인 실행을 trace로 기록하고 trace ID를 출력할 수 있다 ② 규칙 점수와 LLM 채점 점수(0~1)를 `create_score`로 trace에 남길 수 있다 |

## 3. 확인 방법의 원칙

- 모델 답은 실행마다 달라진다. 답이 하나로 정해지는 질문(곱셈, 이름 기억)과 구조(메시지 칸, 노드 순서, 청크 수, 도구 이름)와 코드로 판정한다.
- 명령 한 번으로 끝나야 한다. 서버가 필요한 실습은 과제 파일이 잠깐 띄우고 끈다(3-2 stdio, 3-3 빈 포트).
- 사내망 전용(RAGaaS, 사내 게이트웨이의 도구 호출·구조화 출력, 강의장 Langfuse)은 사외에서 ❔(확인 불가)로 처리하고 사내 점검 때 확인한다. 사내 게이트웨이의 `bind_tools`는 1일차 점심 점검에 넣는다.

## 4. 근거

- 1차 목표 조사(실습별 12개): 실습마다 교안 PDF·원본 코드·노트북 spec을 읽은 서브에이전트 결과.
- 챗봇 트랙 설계: `dev/demos/rag_evolution/`(강사 데모 앱, 단계 순서 1 날것 API → 2 템플릿 → 3 LCEL·기억 → 4 Tool → 5 LangGraph → 6 RAG …)과 14차수 고객사 조정안(챗봇 실습 확대, 1·2일차 1시간씩, Streamlit은 챗봇에 통합, Multi-Agent·LangGraph 축소, RAGaaS 확대).
- M2 독립 과제 결정: MCP·A2A 서버와 Streamlit 재실행이 맞지 않고, 4-3 캡스톤이 터미널 리서치 시스템이라 챗봇과 이어지지 않는다. 대신 MCP 도구·체크포인터·SKILL.md·Langfuse 점수가 캡스톤으로 이어진다.
