# 11차수 수강생 피드백 정리

원본 두 개(만족도설문 PDF, 수강생 피드백 XLSX)를 한 문서로 합쳤다. 원본 파일은 이 공개판에 포함되어 있지 않다. 원문 표현은 오탈자까지 그대로 옮겼다.

## 한눈에 보기

| 모듈 | 과정 만족도 | 강사 만족도 | 응답 수 |

- **캡스톤 시간 부족, 미리 안내** — 피드백 5번 항목.

## 2. 피드백 수정 요청 (5건)

각 항목은 엑셀의 세 열을 그대로 나눴다: **수강생 요청 → 운영 측 코멘트 → 반영 현황**.

### 2.1 개발 환경 셋팅 시간

**수강생 요청**
> 개발환경 셋팅에 시간이 너무 오래걸린다.
> 강의장PC에서는 되는데 원격PC에서 잘 안돼서 배운 내용 적용이 어려울 것 같다

**운영 측 코멘트** — 수업 초반에 강사가 아래 내용을 구두로 한 번 더 안내 (입과자 메일로도 안내됨)

- 교육 후 업무에 돌아가면 셋팅을 어떻게 시작할지 모르겠다는 사람이 늘 있다. 교육–업무 연계를 위해 실습 환경 셋팅부터 차근차근 안내하니, 초반 시간이 걸려도 양해 부탁.
- 초반 차수에는 원격으로 개인 PC에 셋팅하도록 했으나, 개인별 사내 PC 환경이 달라 모든 경우를 대응하기 어려워 **강의장 PC 기준**으로 설치를 안내한다.
- 업무 PC에 바로 설치되지 않아 불편하지만, 한 번 해 두면 업무 복귀 후 가이드대로 그대로 설치할 수 있다.
- Python 경험이 있으면 원격 PC로 진행해도 되지만, PC 오류에 100% 대응하기는 어렵다.
- 셋팅 중 어려우면 손을 들면 보조강사와 함께 대응.

**반영 현황**

| 구분 | 내용 |
|---|---|
| 현재 반영 | 셋팅 목적(교육–업무 연계)을 강사가 구두 안내, 입과자 메일 병행 |
| 현재 반영 | 강의장 PC 기준 설치로 통일 (실제 소요 약 1.5~2.0시간) |
| 현재 반영 | 어려움 발생 시 손들어 질문 → 강사가 직접 대응 |
| 반영 가능 | 사전 셋팅으로 시간 단축: 일찍 도착해 강의장 PC에 로그인 후 진행, 또는 개인 PC에서 원격으로 강의장 PC에 접속 |
| 반영 가능 | 20명 이상 차수는 보조강사 배정 시 효율 상승 기대 (현재 보조강사 없음) |
| 불가 | 원격/업무용 PC 셋팅 가이드 별도 제공 — 보안상 강사 사전 접속 불가, 사내 타 프로그램과 설정 충돌 우려 |
| 불가 | 강사 사전 셋팅 — 개인 계정별 로컬 PC 초기화 정책 |

### 2.2 이론 설명 확대 ("왜·언제 쓰는지")

**수강생 요청**
> 이론 설명을 늘렸으면 좋겠다.
>
> 기능, 함수에 대한 설명은 있지만 왜, 언제, 어떤 시나리에서 사용하는지가 없어서 강의와 실습 내용을 온전히 이해하기 어려웠습니다.
>
> 전반적으로 실습에 대한 설명이 좀 더 추가되면 좋겠습니다.
>
> 실습 보다 개념 위주로 많이 해주세요. 어차피 코딩은 ai 가 합니다.

**운영 측 코멘트** — 코드 실습 비중을 줄이고 이론 설명·코드 리뷰 확대 (특히 M1)

- 필요한 이론은 LangChain·LangGraph 코드 기능보다 **AI Agent 구조·설계** 쪽이다.
- 모든 주요 개념에 **"왜 배우는지/왜 중요한지"**와 **"비유 및 실제 사례의 적용 포인트"**가 있어야 한다.
- 코드 풀이 때 기능보다 역할·개념·왜 쓰는지·언제 쓰는지를 설명한다.
- M1은 복잡한 코드 실습을 줄이고 개념 설명·코드 리뷰 위주로 바꿔도 좋다.
- 강사별 편차를 줄이도록 교안·커리큘럼 통일이 필요하다. 설명 분량이 늘어 커리큘럼 조정이 필요하면 한꺼번에 정리해 달라.

예시 1 — 1-2 교안 context window

1. 정의: 모델이 1번의 요청에서 읽을 수 있는 토큰 범위
2. 중요한 이유: LLM 설계 한계를 결정함 → compaction 필요
   - AI는 사람과 달리 매번 대화를 통째로 읽어야 문맥을 파악한다 (단기 기억).
   - 대용량을 다 못 읽어 일부를 잊고 할루시네이션이 생길 수 있다.
   - 길어질수록 누적 컨텍스트가 매 턴 입력돼 비용이 커진다.
   - 그래서 RAG, LangGraph의 state 관리·설계가 중요하다 (후반부 실습과 연결).
3. 결론: context window를 이해해야 품질 좋은 LLM Agent를 설계할 수 있다. (배우는 이유 강조)

예시 2 — 1-3 교안 Tool Calling

- Tool 생성·목록 설정·mapping 같은 기능 설명보다, **모델이 툴을 어떻게 고르는지**, **반복 호출 흐름이 어떤지**를 이론과 구조 중심으로 설명.

**반영 현황**

| 구분 | 내용 |
|---|---|
| 현재 반영 | 주요 개념마다 "왜 배우는지/왜 중요한지" + "비유·실제 사례 적용 포인트"를 강사가 설명 |
| 현재 반영 | 강사용 설명 가이드가 컨플루언스 페이지와 10차수 하단 댓글에 있어 강사별 편차 최소화 |
| 현재 반영 | 교안·실습 코드 수정은 강사가 직접 수정 (수정 주체 명확) |
| 반영 가능 | M1 실습 축소: streamlit 실습은 Agent 시각화 용도라 코드 작성 대신 단순 실행으로 대체 → 확보한 시간을 이론·코드 리뷰(AI Agent 구조·설계, Tool 선택/반복 호출 흐름 등)에 배분 |
| 제약 | 총 시수가 고정이라 이론 확대는 실습 축소 범위 안에서만 가능 |

### 2.3 강의자료만으로 실습이 어렵다

**수강생 요청**
> 강의자료에 대한 이해바탕으로 실습을 할 수 있지 않음, 강의자료 부실
>
> 실제 실습에서는 교재에 없는 부분들이 종종 나와서 실습을 하려면 따로 찾아보거나 강사님이 같이 실습 풀이를 해줄 때 까지 기다려야하는 경우가 많음

**운영 측 코멘트**
> 8차수 이후 종종 있는 피드백. 분량 때문에 삭제한 것인지, 변경 히스토리를 아는지 문의. (단순 수강생 수준 문제일 수도)

**반영 현황**

| 구분 | 내용 |
|---|---|
| 현재 반영 | 8차수 이후 교재에서 삭제된 내용 없음. 오히려 이론 예시·코드 안내가 추가되어 분량 증가 |
| 현재 반영 | "교재에 없다"고 느끼는 부분은 이전 일차(예: 2일차→1일차)에 1회 이상 다룬 내용 |
| 현재 반영 | 실습 도중에도 완성 코드·해설 확인 가능 |
| 현재 반영 | M2 시작 전 M1 서머리 노트 배포 |
| 현재 반영 | M1 셋팅 때 파이썬 기초 테스트(5문제)로 수준 파악 — 20명 중 5명 이상이 LLM Assistant로 풀고, 평균 5문제 중 3문제 정답 |
| 반영 가능 | 교재 보완은 완료 상태로 추가 반영 없음 (수강생 수준 편차 이슈로 판단) |
| 제안 | 실습 시작 때 "이 내용은 O일차 X교안 참고"처럼 선행 학습 위치를 구두 안내해 검색 시간 단축 |

### 2.4 CodeMate 활용

**수강생 요청**
> 실습 보다 개념 위주로 많이 해주세요. 어차피 코딩은 ai 가 합니다.

**운영 측 코멘트** — "코딩은 AI가 하는데 왜 코드를 배우는가"라는 교육 목표를 설명해 달라

- CodeMate·Claude Code가 코드를 짜도 설계는 사람이 한다. 그래서 코드를 뜯어보고 실습하며 깊이 이해하려는 것이다. 실습 코드를 매끄럽게 작성하는 게 목표가 아니므로 CodeMate를 적극 쓰고, AI Agent 배경 이론과 설계의 핵심을 이해하는 게 목표다.
- API 호출 에러, 할루시네이션 같은 예상 못 한 오류가 나면, 코드를 조금이라도 알아야 원인을 빨리 찾는다.
- 코드 구조를 알고 명확히 지시하면, 뭉뚱그린 질문보다 결과가 좋고 엉뚱한 재시도로 인한 토큰(비용) 낭비가 준다.
- 참고: 사내 SW 개발자 대부분은 Claude Code 사용 가능 (비개발자는 불가). 실습 중 CodeMate를 적극 써도 된다고 언급.
- CodeMate 설치·로그인 후 실습하는 방법을 강사가 시연하거나 컨플루언스 페이지("1. 입과자 실습환경 가이드" 하위)를 안내. 수강생용 프롬프트 예시는 준비·동작 확인 완료.

**반영 현황**

| 구분 | 내용 |
|---|---|
| 현재 반영 | "코딩은 AI가 해도 왜 코드를 배우는가"(langchain/langgraph 학습 이유)를 1-1 교안에 추가 |
| 현재 반영 | 실습 중 1개를 CodeMate 활용 예제로 시연 (15분 내외) |
| 현재 반영 | CodeMate 활용 방법·프롬프트 예시를 각 PDF 교안에 추가 |
| 현재 반영 | CodeMate를 쓸 수 없으면 강사, 솔루션(정답 코드), PDF 내용으로 대체 |
| 확인 필요 | Claude Code 허용 범위(개발자만)는 강사가 확인 불가 → 운영 측이 안내 문구를 확정하면 강사가 구두 안내 |

### 2.5 캡스톤 시간 부족 (M2)

**수강생 요청**
> (M2) 캡스톤 과제할 시간이 부족함
> (M2) 마지막 과제가 교육 초반에 안내되면 좋을 것 같음

**운영 측 코멘트**

- M1·M2 모두 1일차에 강사 소개 후 과정 커리큘럼 전체를 소개하는 세션 추가.
- 컨플루언스 "2. 커리큘럼" 페이지에서 상시 확인할 수 있다고 언급.
- 특히 M2 1일차에 캡스톤 프로젝트를 예고해 주제를 미리 생각하게 한다.
- 업데이트된 커리큘럼과 학습목표를 주면 반영 예정 (엑셀 선호).

**반영 현황**

| 구분 | 내용 |
|---|---|
| 현재 반영 | M1·M2 1일차 강사 소개 후 커리큘럼 전체 소개(30분 이내) |
| 현재 반영 | 실습이 빨리 끝나면 중간에 캡스톤 ideation·코딩 진행 안내 |
| 현재 반영 | 캡스톤 안내 자료(주제·산출물)는 컨플루언스에 있음 |
| 현재 반영 | M2 1일차에 이전 차수 캡스톤 우수사례와 함께 현 기수 캡스톤 예고 |
| 반영 가능 | 최신 커리큘럼 PPT 작성 완료 → 운영 측에 제공 예정 |

## 3. 진행 원칙

위 1·2절에서 나온 강사 진행 원칙이다. 설문에서는 실습을 늘려 달라는 요청이, 운영 측에서는 개념의 "왜"를 더 설명해 달라는 요청이 나왔다. 이 과정에서는 둘을 CodeMate 실습으로 묶는다. 코드 작성은 CodeMate에 맡기고, 강사는 개념의 이유와 코드 리뷰에 시간을 쓴다.

1. **과정 소개와 캡스톤 예고.** 1일차와 3일차 시작 때 강사 소개 다음에 과정 커리큘럼 전체를 소개한다(30분 이내). 컨플루언스 "2. 커리큘럼" 페이지에서 언제든 볼 수 있다고 알린다. 3일차에는 이전 차수 캡스톤 우수사례를 보여 주며 캡스톤을 예고하고, 주제를 미리 생각하게 한다. 이 30분을 어느 블록에서 뺄지는 아직 정하지 않았다.
2. **코드를 배우는 이유.** 1.1에서 "코딩은 AI가 해도 왜 코드를 보는가"를 먼저 말한다. 설계는 사람이 한다. 코드를 알면 API 오류나 할루시네이션의 원인을 빨리 찾는다. 코드 구조를 알고 지시하면 결과가 좋고 엉뚱한 재시도로 버리는 토큰이 준다.
3. **개념은 "정의 → 왜 중요한가 → 어디에 연결되는가" 순서로 설명한다.** 함수 기능보다 역할·쓰는 이유·쓰는 시점을 말한다.
   - 1.2.2 Context Window: 한 번의 요청에서 읽을 수 있는 토큰 범위다. 모델은 매번 대화를 통째로 다시 읽는다. 넘치면 앞부분을 잃고 할루시네이션이 생길 수 있고, 길수록 매 턴 비용이 커진다. 그래서 요약(compaction), RAG(2.1), LangGraph의 state 설계(2.2)가 필요하다.
   - 1.3.2 Tool Calling: 도구를 만들고 등록하는 방법보다, 모델이 도구를 어떻게 고르는지와 호출이 어떻게 반복되는지를 구조로 설명한다.
4. **선행 학습 위치 안내.** 실습을 시작할 때 "이 내용은 O일차 X 블록에서 다뤘다"고 알려 준다. 교재에 없다고 느끼는 내용은 대부분 앞 일차에서 한 번 이상 다룬 것이다.
5. **화면 크기.** 코드와 Langfuse 화면은 뒷자리에서도 읽히도록 확대해서 보여 준다.
6. **환경 셋팅.** 강의장 PC 기준으로 설치한다(약 1.5~2시간). 시작 전에 셋팅을 직접 하는 목적(업무 복귀 후 같은 순서로 설치)을 말하고, 막히면 손을 들게 한다. 업무 PC용 가이드는 따로 제공하지 않는다.
