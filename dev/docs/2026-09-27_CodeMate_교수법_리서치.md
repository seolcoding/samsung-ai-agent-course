# CodeMate 페어 프로그래밍 교수법 리서치 (2026-09-27)

Copilot류 Coding AI를 쓰며 가르치는 방법을 두 갈래로 조사했다. 하나는 컴퓨팅 교육 연구(2023~2026)이고, 다른 하나는 공식 교육 자료와 현장 워크숍이다.
연구 대상은 대부분 대학 CS1 학생이나 청소년이다. 성인 비개발자가 짧은 워크숍에서 배운 연구는 찾지 못했다. "이 과정에 적용"은 그 결과를 이 과정에 옮겨 본 추론이다.

## 1. 결론

1. **AI를 쓰면 과제는 끝내지만, 이해하지 못한 채 끝낼 수 있다.** 어려워하는 학습자일수록 이 착각이 크다. 우리 수강생 프로필(비개발자 다수)과 가장 직접 겹치는 위험이다. → 근거 A4, A5, A6
2. **효과를 가르는 것은 AI를 쓰는지가 아니라 어떻게 쓰는지다.** 설명을 함께 받는 사용은 이해도를 지켰다. 통째로 맡기거나 디버깅을 떠넘기는 사용은 이해도를 떨어뜨렸다. → A5
3. **지시문의 품질은 말투가 아니라 담긴 정보가 정한다.** 영어 용어보다 입력·출력·예외를 빠짐없이 적는 틀이 중요하다. → A2, B1
4. **"주석으로 시키기"는 Copilot 공식 교육의 기본기다.** 다만 노트북(.ipynb) 셀 안의 자동완성은 불안정하다는 신고가 있다. 주력 경로는 채팅이나 셀 인라인 채팅으로 잡는다. → B1, B2
5. **CodeMate의 실제 기능은 공개 자료로 확인할 수 없다.** 그래서 강의장 사전 점검 결과에 따라 실습 방식이 갈린다. → 4절

## 2. 연구 근거 (A)

| # | 기법 | 연구 결과 | 이 과정에 적용 |
|---|---|---|---|
| A1 | 쪼개서 시키기 | 33명이 과제 45개를 풀었다. 92%가 시작하자마자 AI를 불렀고, 66%는 과제를 통째로 붙여넣었다. 이 방식은 작성 점수가 가장 높았지만 이어진 **수정 과제 점수가 가장 낮았다.** | 셀 하나에 하위 목표 하나. 생성 직후 바로 수정·재지시 과제를 붙인다. |
| A2 | 명세 먼저 | 초보자 120명의 첫 프롬프트 성공률은 22%, 최종 성공률은 57%였다. 실패의 원인은 용어를 모르는 것이 아니라 **빠진 정보**였다. | 지시문 틀을 준다: 입력, 출력 형식, 예외, 사용할 라이브러리, 하지 말 것. |
| A3 | 읽기를 따로 가르친다 | LLM 코드를 읽고 판단한 성공률은 32.5%였다. 원인은 모국어가 아닌 영어, 문법 지식 부족, 기계 출력을 믿는 경향이었다. | 실행 전에 읽는 단계를 둔다. CodeMate에게 한국어 한 줄 주석을 달게 하고, 틀린 줄 찾기 과제를 낸다. |
| A4 | 예측 후 실행 | 21명 중 20명이 과제를 끝냈다. 하지만 어려워하던 학생은 **실제보다 잘했다고 믿는 착각**을 안고 끝났다. | 실행 전에 결과를 한 줄로 예측하고, 실행 후 비교한다. |
| A5 | 설명을 요구하며 쓰기 | 52명 무작위 실험에서 AI 그룹 퀴즈 50%, 직접 코딩 그룹 67%였다. AI 그룹 안에서도 "코드와 설명을 함께 받기"는 65% 이상, "통째로 맡기기·디버깅 떠넘기기"는 40% 미만이었다. | 지시문 끝에 "왜 이렇게 했는지 3줄로 설명"을 기본으로 붙인다. 에러가 나면 원인을 먼저 자기 말로 적고 나서 AI에 묻는다. |
| A6 | 답을 바로 주지 않는 도우미 | 고교생 약 1,000명 실험. 일반 GPT는 연습 점수를 48% 올렸지만, AI를 뺀 시험에서는 17% 낮았다. 힌트만 주도록 설계한 GPT는 이 손실을 대부분 막았다. | 개념 구간은 "힌트·질문만", 구현 구간은 "생성 허용"으로 나눈다. CodeMate 모드나 지시문으로 구분한다. |
| A7 | 가드레일은 샌다 | CS50 Duck에 "코드 주지 마"라고 지시했는데도 메시지의 22%에 코드가 들어 있었다. | 규칙을 적었다고 지켜진다고 가정하지 않고 결과를 표본 점검한다. 이것 자체가 하네스 수업 사례가 된다. |
| A8 | 의사코드 먼저 | 372명이 12주 동안 쓴 CodeAid는 답변의 약 80%가 정확했다. 답변은 주로 설명과 의사코드였다. | "먼저 한국어 의사코드를 보여 주고, 내가 승인하면 코드로 바꿔라"의 2단계 지시. |
| A9 | 질문에 답한 뒤 공개 | 7가지 기법을 비교했다(82명, 42명). 단계 질문 후 코드 공개, 변수값 예측 후 설명이 부담 대비 효과가 좋았다. | "이 노드를 지나면 `state['messages']` 길이는?" 같은 예측 셀. |
| A10 | 프롬프트 문제 | 코드 대신 지시문을 쓰고, 그 지시로 만든 코드가 테스트를 통과하면 정답이다. 반응은 좋았으나 효과 수치는 없다. | 테스트 셀을 먼저 주고 "지시문만 써서 통과시키기". |
| A11 | 쉬운 말 설명 → 재생성 | 학생이 코드를 쉬운 말로 설명하면 LLM이 그 설명으로 코드를 다시 만들고, 테스트로 설명의 정확도를 본다. 효과 수치는 확인하지 못했다. | 받은 원본 코드를 한국어로 설명해 CodeMate가 다시 만들게 한다. 원본을 유지하는 방침과 맞는다. |
| A12 | 좋은 편집자 기르기 | 강사 20명 인터뷰의 공통 제안: 코드 읽기·비평 비중 늘리기, AI 결과 리뷰, 먼저 풀어 보고 AI와 비교하기. | 리뷰 중심. 11차수 호평(구조 분석·리뷰 중심)과 같은 방향이다. |

찾지 못한 것: 초보자 대상으로 "테스트를 먼저 쓰고 AI가 생성"하는 방식을 직접 비교한 연구가 없다. 주석 기반 생성과 AI 도우미를 결합한 실증 연구도 없다. AI와의 드라이버/내비게이터 역할 분담 연구는 결과가 엇갈린다.

## 3. 공식 교육·현장 자료 (B)

| # | 내용 | 이 과정에 적용 |
|---|---|---|
| B1 | **Copilot 공식 교육(MS Learn "4S")**: 한 가지만(Single), 구체적으로(Specific), 짧게(Short), 관련 파일을 열어 두기(Surround). 코드 위에 **주석으로 단계를 적으면** Copilot이 채운다. 결과가 틀리면 **코드를 지우고 주석을 보강해 다시 받는다.** 예시를 주는 개수(0·1·여러 개)도 따로 가르친다. | 실습 셀의 TODO를 주석 지시문으로 쓴다. "나쁜 주석 → 좋은 주석" 비교를 한 번 시연한다. 틀리면 코드를 고치지 말고 주석을 고쳐 재지시한다. |
| B2 | **VS Code 노트북 + Copilot**: 셀에서 Ctrl/Cmd+I로 인라인 채팅, "Accept and Run", 셀 출력을 채팅에 붙이기, 에이전트의 셀 수정·실행·오류 수정 반복. 반면 2026-09 VS Code 1.134~1.136에서는 **.ipynb 셀의 인라인 자동완성이 실패한다는 신고**가 있다. | 주력 경로는 인라인 채팅·채팅 패널로 잡고, 자동완성은 되면 쓰는 보조로 둔다. 에러 출력 → 채팅에 붙이기 → 수정 → 재실행을 "루프" 실습으로 만든다. |
| B3 | **Roo Code 모드**: Ask(읽기만), Architect(계획·마크다운만), Code(구현), Debug, Orchestrator. 커스텀 모드와 규칙 파일(`.roo/rules/`)을 지원한다. **2026-05-15 서비스 종료**됐다. **.ipynb를 편집하다 파일이 깨진 공식 이슈**가 있다. | Ask → Architect → Code 순서로 "계획 먼저, 구현 나중"을 가르칠 수 있다. 에이전트에게 .ipynb를 직접 고치게 하는 실습은 위험하다. `lessons/work/`의 `.py`를 고치게 하고 노트북에서 import해 실행한다. |

## 4. CodeMate에 대해 확인된 것과 강의장에서 확인할 것

- 공개 자료에 "CodeMate"라는 삼성 도구는 **없다.** 같은 이름의 제품은 삼성과 무관한 회사(이안) 것이다.
- 공개 보도로 확인된 삼성 도구: DX부문 code.i(삼성 가우스 기반, 개발자 약 60% 사용), DX부문 Cline(2025-06 베타). DS부문의 "DS 어시스턴트"(2023 보도)는 원문을 보지 못해 미검증이다.
- AGENTS.md의 "Roo Code 계열" 메모도 미검증이다. Roo Code는 이미 종료됐다.

**강의장 사전 점검 목록** (결과에 따라 실습 방식이 갈린다)

1. 모드 목록: Ask/Architect/Code 같은 구분이 있는가
2. 규칙 파일: 프로젝트 지침 파일을 쓸 수 있는가, 경로는 어디인가
3. 노트북: .ipynb 셀을 안전하게 편집하는가(파일이 깨지지 않는가)
4. 자동완성: .ipynb 셀 안에서 주석 아래에 코드가 제안되는가
5. 셀 출력(에러)을 채팅에 붙일 수 있는가

## 5. 교안에 넣을 교수법 (제안)

**범위(2026-09-27 확정)**: 내용·순서·아웃라인·실습 코드는 바꾸지 않고 전달 방식만 바꾼다. 아래 순서의 목표 코드는 언제나 받은 원본(`course/ChapterNN/code/raw/`)이다. CodeMate가 만든 코드는 원본과 비교하는 재료로만 쓴다.

한 블록의 CodeMate 실습은 아래 순서를 기본으로 한다.

1. **예측**: 원본 코드를 읽고 결과를 한 줄로 예측한다. (A3, A4, A9)
2. **실행과 비교**: 원본을 실행하고 예측과 비교한다.
3. **주석 지시문 작성**: 지시문 틀(입력·출력·예외·하지 말 것)에 맞춰 셀에 주석으로 쓴다. 끝에 "왜 이렇게 했는지 3줄 설명"을 붙인다. (A2, A5, B1)
4. **CodeMate 생성**: 한 번에 하위 목표 하나만 시킨다. (A1)
5. **리뷰 체크리스트**: 실행되는가 / 요구한 것만 했는가 / 조용히 틀린 값은 없는가 / 내 말로 설명할 수 있는가. (B5, A12)
6. **재지시와 원본 대조**: 틀리면 코드를 직접 고치지 말고 주석을 보강해 다시 시킨다. 마지막에 원본 코드와 나란히 비교한다. (B1, A11)

- 개념 구간에서는 CodeMate를 설명·힌트 용도로만 쓰고, 구현 구간에서만 생성을 맡긴다. (A6)
- 사용자가 낸 "주석 → CodeMate 지시" 아이디어는 3·6단계에 들어간다. 주석을 쓰는 것 자체는 공식 교육(B1)의 뒷받침이 있다. 주석을 받아 코드를 채우는 주체(자동완성이냐 채팅이냐)는 4절 점검 4번의 결과로 정한다.
