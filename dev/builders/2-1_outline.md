## 4. 실행 제약·위험과 노트북 처리 제안

| 항목 | 내용 | 처리 제안 |
|---|---|---|
| 04 거부 결함 | 원본은 `rejection_messages`를 만들기만 하고 상태에 넣지 않는다. `app.invoke(None, ...)`가 멈춘 지점부터 그대로 재개해 `send_email`이 실행된다 | **권장**: 보이는 코드는 솔루션(update_state 포함)으로 넣어 실제로 막는다. 그 아래 "AI에게 물어보기": "이 셀에서 `app.update_state` 줄이 없으면 무슨 일이 생기는지, 출력의 어느 줄로 알 수 있는지 설명해 달라고 합니다." 🟢 "도구가 그대로 실행되어 `[실제 전송]`이 찍힌다"를 짚었다 ⛔ "거부 메시지를 만들었으니 안 보낸다"고 답했다. 강사용 상자에 원본 결함을 기록한다. 대안(질문 3): 원본 그대로 실행해 `[실제 전송]`이 찍히는 것을 먼저 보여 주고 고치게 한다 |
| 가짜 메일 도구 | `send_email`은 `print`만 한다. 실제 메일 서버 호출 없음 | "실제 전송"은 "도구가 실행되었다"는 뜻이라고 수강생 글에 한 줄 적는다 |
| 05 `input()` | 파일 끝 `if __name__ == '__main__':` 블록이 노트북에서도 실행된다(`__name__`이 `'__main__'`). VS Code 노트북은 위쪽 입력창으로 `input()`을 받는다. 자동 실행(nbconvert·QC `--execute`)에서는 입력을 못 받아 오류 | 함수 정의는 셀로 그대로 두고, 마지막 실행 셀만 따로 둔다. 셀 위에 "화면 위쪽 입력창에 요청을 적고, 이어서 y/n/q를 입력합니다"를 쓴다. QC 실행에서는 이 셀을 건너뛰도록 표시(태그 등)한다. 새 위젯은 만들지 않는다 |
| 05 입력 반복 | 잘못된 값을 넣으면 같은 질문이 반복되고, 에이전트가 도구를 계속 부르면 루프가 길어진다 | q로 끝낼 수 있음을 셀 위에 적는다. 멈추면 커널 중단(■) |
| 도구 호출 지원 | 03·04·05는 `bind_tools` 도구 호출이 필요하다. 사내 게이트웨이의 도구 호출 동작은 이 목차 작성 중 확인하지 않았다(`docs/VALIDATION.md`는 "Chapter01 LangGraph 정상 종료"만 기록, 환경 표기 없음) | 강의장 사전 확인 목록에 넣는다. 사외는 `openai`(`gpt-6-luna`는 `get_llm()`이 Chat Completions로 고정) |
| 모델이 도구를 안 부름 | 04·05에서 모델이 도구 없이 답하면 `tool_calls`가 비어 1단계 출력이 빈다 | ⛔ 기준에 "대기 중인 도구 호출이 비었다 → 셀을 다시 실행"을 넣는다 |
| Mermaid | `draw_mermaid()`는 글자 출력. 그림(`draw_mermaid_png`)은 외부 서비스를 부른다 | 글자 출력만 쓴다(사내망) |
| 실행 순서 | 04는 같은 `thread_id`로 1단계 → 2단계를 이어 간다. 1단계 셀을 다시 실행하지 않고 2단계만 다시 실행하면 결과가 달라진다 | 셀 위에 "1단계부터 차례로 실행"을 적는다 |
| 실행 시간 | 파일당 LLM 1~6회. 긴 실행 없음 | — |
| 파일 쓰기 | 없음(`MemorySaver`는 메모리. `SqliteSaver`는 import만) | — |
