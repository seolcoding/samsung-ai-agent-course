- **원칙**: PDF 순서를 그대로 따른다. 내용과 코드는 바꾸지 않는다. 바꾸는 것은 전달 방식뿐이다.
- **원본 실행**: `%run`으로 그대로 실행한다. 한 파일은 한 번만 실행한다(파일 맨 위에서 API를 바로 호출하기 때문).
- **A/B/C**: 뼈대·실행·실습·퀴즈는 같고 설명 셀만 다르다.
  - A = 슬라이드 문구만
  - B = 슬라이드 요약 + 코드 연결
  - C = "왜 배우나"를 새로 쓴다. 문장마다 근거(PDF 쪽·커리큘럼·11차수 피드백)를 표시한다.
- **퀴즈 형식은 3종으로 제한**: 객관식, 예측 후 실행, 순서 맞추기. CodeMate 리뷰에만 체크리스트를 쓴다.
- **실행 출력의 숫자는 정답으로 고정하지 않는다**: 토큰 수, 조각 수는 실행할 때마다, 환경마다 달라진다. "출력에서 직접 읽기"로 묻고, 값이 없으면 "이 환경에서는 제공되지 않음"이라고 셀에 적는다.

- **C. 지시로 다시 만들고 비교 (선택, 조기 완료자)**: 원본의 동작(입력·출력·예외)을 말로 적어 `lessons/work/01_requests_mine.py`를 만들게 한다. VS Code "파일 비교(Compare Selected)"로 원본과 나란히 보고 차이를 적는다. 틀리면 지시문을 보강해 다시 시킨다.

## 원본끼리 어긋나는 곳 (고치지 않고 볼 지점으로 알린다)

1. **역할 이름**: p18은 System, `02_openai.py`는 `developer`(주석: "시스템 지시"), `01_requests.py`는 user만 쓴다.
2. **Assistant 메시지**: 02는 `response_1.output`을 통째로 이어 붙여서, 화면에 글자로 보이지 않는다.
3. **temperature**
   - 01은 `OPENAI_MODEL=gpt-6-luna`일 때만 temperature를 뺀다. 사내 경로에서는 0.5가 그대로 전송된다.
   - 02의 예시는 주석(docstring) 안에 있어 실행되지 않는다.
4. **API 모양과 사내 지원**: 01은 `messages`(Chat Completions), 02는 `input`(Responses API)을 쓴다. 사내 게이트웨이가 Responses API를 지원하는지는 **미확인**이다.
5. **03(raw) 스트리밍**: 주석과 달리 `print(chunk)`로 조각 객체를 그대로 찍는다(정답본은 `chunk.content`). 실습 B의 소재다.
6. **조각 수와 토큰 수**: 스트리밍 조각 수와 출력 토큰 수는 다르다. p6에는 "조각이 순서대로 쌓인다"까지만 연결한다.
7. **사내 usage 제공 여부**: 사내 경로에서 `usage`와 `reasoning_tokens`가 오는지 미확인이다. 03은 `stream_usage` 설정이 없어서, 마지막 조각에 usage가 없을 수 있다.
