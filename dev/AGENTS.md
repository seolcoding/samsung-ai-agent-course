# AGENTS.md — 교안 노트북·과제 제작 (dev/, v2.0, 2026-10-19)

루트 `AGENTS.md`를 따른다. 이 문서는 노트북과 과제를 만드는 방식만 정한다.

## 1. 노트북 공통

- 빌더(`dev/builders/`)가 수강생본 `course/ChapterNN/notebooks/`와 강사본 `dev/instructor/ChapterNN/`(강사용 메모 포함)을 쓴다.
- 권마다 `<번호>_<이름>_LEC.ipynb`(슬라이드·설명·퀴즈)와 `_LAB.ipynb`(실습). 번호는 PDF 번호, 제목은 `# [LEC] …`/`# [LAB] …`.
- 설명·슬라이드·실행 코드를 한 권 안에 넣는다. 제목 번호(`1.`, `1.1`)와 목차의 `(슬라이드)`·`(퀴즈)` 표시는 `nbkit.py`가 붙인다.
- 수강생은 노트북만 본다. 수강생 글에 `.py`·경로·다른 노트북·CodeMate를 쓰지 않는다. 도구는 "AI"라고 쓴다.
- 수강생 설명은 강의장 PC인 Windows 기준이다(`Ctrl + /`, 맥 키는 적지 않는다).
- 코드 셀 경로는 노트북 폴더 기준이다. 준비 셀이 `sys.path.insert(0, '..')`로 `assets`를 부르고, 실습 자료는 `notebooks/data/`.

## 2. 실습 노트북(LAB)

- `build_lab.py`가 `labs/<폴더>.json`(Chapter02는 `labs/Chapter02/`)과 받은 원본 코드로 조립한다. 원본은 고치지 않고 spec `patch`로 바꾼다.
- 첫 구획은 접힌 준비 셀, 나머지는 보이는 코드 셀이다. 과제 안내 절과 "AI에게 물어보기" 절은 두지 않는다.
- 막혔을 때 안내는 한 줄(`nbkit.SELF_HELP`): 오류 메시지 전체를 AI에게 붙여 넣게 한다.
- LangChain 실습에는 빌더가 디버그 셀(`set_debug(True)`, 기본 켜짐)을 넣는다. 도구 실습엔 `KeyError('input')` 줄은 무시해도 된다는 안내를 붙인다.
- 서버(MCP·A2A)는 셀에서 띄우지 않는다. 빌더가 정답 서버 파일을 노트북 폴더에 쓰고, 수강생은 터미널에서 띄운다.
- 4-3 캡스톤은 `course/Chapter02/capstone/` 폴더와 `build_capstone_guide.py`가 만드는 안내 노트북이다.

### 값 바꾸기판 (M1 전부, M2는 3-2·3-3·3-4·4-1·4-2 — 2026-10-21부터)

- 코드는 완성해서 준다. 바꿔 볼 값 바로 위에 `# ✍️ CHANGE_HERE: <바꾸면 어떻게 될까요?>`를 단다(결과는 미리 말하지 않는다).
- 바꾸는 것은 값이다(프롬프트 문구·질문·`k`·`chunk_size`·`thread_id`·목록 항목). 구조 변경은 개념을 값으로 못 보일 때만, 오류를 내려고 바꾸지 않는다.
- 차이가 구조로 보이는 값을 고른다(도구 호출·청크 수·거친 노드·기억 여부). 절마다 많아야 하나, 한 번에 하나 바꾸고 되돌린다.
- spec `edits`의 `old`(바로 아래 줄에 한 번만 나오는 짧은 조각)·`new`로 복사해 붙여 넣을 값을 준다. 지우는 변경은 `new: [""]`.
- `result`는 셀 아래 접힌 "무슨 일이 생기나"가 된다. 실제로 바꿔 실행한 결과로 쓴다. 🟢/⛔ 기준과 정답 보기는 두지 않는다.

### 객관식판 (3-1만 이 모양으로 빌드, 2026-10-21까지 M2 전부)

- 2026-10-21 사용자 결정으로 M2도 값 바꾸기판이 기본이다(`build_lab.py`의 `CHANGE_M2`). choices 파일은 완성 코드에 넣을 정답 줄의 원천으로 남는다. 아래는 객관식판으로 빌드할 때(`--mc`)의 규칙이다.

- 빈칸 자리에 `# ✅ CHOOSE_HERE: …`와 보기 4개를 주석으로 둔다(`labs/<폴더>.choices.json`). 같은 번호(1️⃣~4️⃣) 줄을 골라 `Ctrl + /`로 푼다.
- 마크다운은 굵은 지시 한 줄과 🟢·⛔ 한 줄씩(`mc_checks`)만 둔다. 개념 설명과 보기별 해설은 접힌 "정답 보기"에 둔다.
- 여러 줄 코드는 한 줄로 억지로 줄이지 않는다(`rewrite: true`). 몸통이 보기뿐이면 맨 밑에 `pass  # 그대로 둡니다`.
- 오답 해설은 실제로 실행한 결과로 쓴다. 정답 번호는 과제마다 섞는다. 바꿀 글은 choices의 `_text`에 둔다.

## 3. 과제 (`course/ChapterNN/tasks/<번호>_task.py`)

- 고급 사용자용이다. 일반 수강생은 노트북(코스)만으로 진행하므로, 노트북은 과제 없이 끝까지 따라갈 수 있어야 한다.
- 실습마다 파일 하나, `tasks/` 바로 아래(예외 `Chapter02/tasks/4-1_skills/`). README 없음. 정답은 `dev/solutions/tasks/`.
- 초보자가 30분 안에 끝낸다: `✍️` 자리 2곳(각 10줄 안팎), 파일 80줄 안팎, 나머지는 완성해서 준다. 목표는 `docs/2026-10-18_실습_학습목표.md`.
- 사내(삼성) 환경 코드만 둔다(사내/사외 분기 없음). 모델·임베딩은 `config`(`get_llm()`, `get_embeddings()`)로 부른다.
- 맨 위 docstring 6줄(제목, ✍️ 할 곳, ▶️ 실행, ✅ 확인, 🆘 막히면). 자리마다 `# ✍️ N. <할 일>`과 `# ✨ <핵심어>` 두 줄만 둔다.
- 채우기 전에도 돈다(`NotImplementedError`). 판정은 파일 안 확인 코드의 구조 검사로 🟢/⛔/❔를 낸다(LLM 채점·채점 스킬 없음).
- 1-2·1-3·1-4·2-1·2-3은 Streamlit 챗봇 앱이다. 화면은 파일 맨 아래에 넣고, python으로 실행하면 스스로 `streamlit run`으로 뜬다.
- 챗봇 앱은 말풍선에 ⚠️ 오류를 보이고 멈추지 않는다. 확인은 사이드바 "✅ 과제 확인", 터미널 과제는 실행 끝 `✅ 확인`.

## 4. LangGraph·출력 모양

- 노드는 바뀐 키만 dict로 반환하고 분기는 `add_conditional_edges`로 한다(`Command` 안 씀).
- 갈림길 함수에는 반환 타입 `Literal[...]`을 단다. 없으면 `draw()` 그림에서 갈래가 빠진다.
- 결과는 `results = <그래프명>_result["messages"]` 뒤 `m.pretty_print()` 루프로 보인다. 결과 변수 이름에 그래프 이름을 넣는다.

## 5. 강의 노트북(LEC)·HTML

- 설명은 슬라이드 요약 + 내용 있는 곳만 "왜 배우나". 슬라이드는 PDF.js로 PDF를 그린다(`show_slides("1-2", [9, 10])`).
- 퀴즈는 4지선다, 장면을 주고 "무엇을 쓰나/어떻게 되나"를 묻는다. 암기·쪽·목차 문항은 쓰지 않는다. 판정 근거는 `docs/quiz_review/`.
- 동작하는 HTML은 코드 셀의 `display(HTML(...))`로 낸다. 공용 위젯은 `course/ChapterNN/assets/widgets.py`(예시 `demos/html_embed_demo.ipynb`).
- VS Code는 한 노트북 출력을 한 화면에 그린다. 앱마다 고유한 바깥 `id`를 두고 스크립트는 `(() => { ... })();`로 감싼다.
- 사내망이라 외부 주소(CDN)를 넣지 않는다. 이미지는 `data:` URI, 스크립트는 `<script>` 본문, 라이브러리는 `assets/vendor/<이름>-<버전>.js`.
