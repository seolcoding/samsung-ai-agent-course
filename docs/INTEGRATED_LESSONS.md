# 통합 교안 조립 지도

최종 교안은 수업에서 바로 여는 **주피터 노트북**이다. 적절한 그림과 쉬운 설명을 보여 주고, 그 자리에서 코드를 실행하며, CodeMate 실습과 결과 검토까지 진행한다. 기존 PDF·슬라이드 해설·코드의 순서를 그대로 복제하지 않고 **핵심 질문 → 그림과 설명 → 관련 코드와 실행 → CodeMate 작업 → 결과 검토**로 내용을 해체해 다시 엮는다. 발표용 셀 유형은 내용을 완성한 다음에 다듬는다.

일차의 진행 순서는 2026-09-03 커리큘럼 수정본을 기준으로 한다. 학습자에게 보이는 제목은 `1.1`, `1.1.1`처럼 **내용 번호**로 적는다. 분 단위 배정은 강사용 [시간표](INSTRUCTOR_TIMING.md)에만 둔다. 강의 직전에는 컨플루언스의 최신 안내와 대조한다.

## 최종 파일 단위

```text
lessons/
  _template.ipynb     한 주제의 설명·실행·실습 셀 배열을 복사할 때 사용
  _prototype_agent_loop.ipynb  1.1.2·1.1.3의 완성 모습 시범본
  assets/             노트북에 첨부한 그림의 원본
  day01.ipynb          Agent 사고방식 → LLM API → LangChain
  day02.ipynb          RAG → LangGraph → Multi-Agent·Streamlit
  day03.ipynb          복습 → MCP → A2A → LangGraph 심화
  day04.ipynb          Harness → Langfuse → 캡스톤
```

하루 한 권을 수업 시작부터 끝까지 연다. `day01.ipynb`부터 `day04.ipynb`까지 13개 블록·63개 세부 주제를 작성했다. 실행 코드는 통합 노트북과 `src/courseware/`를 기준으로 한다. 상세 출처·대체 이유는 [LESSON_SOURCES.md](LESSON_SOURCES.md), 검토 기준은 [INSTRUCTOR_GUIDE.md](INSTRUCTOR_GUIDE.md)에 있다. PDF 번호나 기존 `Chapter01`·`Chapter02` 폴더는 **원본 위치**를 찾는 이름이며 통합본의 단위가 아니다.

[`_prototype_agent_loop.ipynb`](../lessons/_prototype_agent_loop.ipynb)는 `1.1.2`·`1.1.3`의 최종 형태를 검토하기 위한 시범본이다. 생성한 `chatbot_vs_agent.png`는 “말로 답하기와 도구 사용”의 차이를 직관적으로 보여 준다. 모델의 제안, 프로그램의 검사·실행, 관찰 뒤 반복이라는 정확한 순서는 `agent_loop.svg`에 별도로 그렸다. 두 그림에는 **의미·볼 지점·표현의 한계**를 바로 아래에 설명한다. 두 그림 모두 노트북 안에 첨부해 파일 하나로 볼 수 있다. 이 시범본의 코드 셀은 외부 API 없이 순서대로 실행된다. 4일치 본문은 `day01.ipynb`부터 `day04.ipynb`에 있으며 시범본은 작성 예제로 남긴다.

## 내용 번호와 원본 배치

일차를 첫 숫자, 커리큘럼 블록을 둘째 숫자, 노트북의 세부 주제를 셋째 숫자로 쓴다. 예: `1.1`은 1일차 Agent 사고방식, `1.1.2`는 Chatbot과 Agent의 차이다. 학습자에게 보이는 노트북에는 이 번호와 제목을 쓰고 진행 시간은 쓰지 않는다. 강사용 배정은 [INSTRUCTOR_TIMING.md](INSTRUCTOR_TIMING.md)에 따로 둔다.

**아래 표는 원본 자료와의 대응 지도다.** 기존 Python 파일 이름은 원본을 찾는 참조이며 수업 중 실행할 경로는 각 통합 노트북에 명시한다.

아래의 각 행은 원본 PDF 한 장이나 Python 파일 하나가 아니라 **설명·그림·실행·실습·검토가 연결되는 주제**다. 같은 PDF 쪽이나 코드를 여러 주제에서 다시 사용할 수 있다.

## 노트북 화면의 흐름

1. Markdown 셀을 **한 화면에 한 핵심 메시지**가 보이도록 나눈다. 먼저 수강생이 답할 질문을 주고, 이해에 필요한 그림과 짧은 설명을 바로 옆에 둔다. 제목에는 `1.1`, `1.1.1` 같은 의미 번호를 쓴다.
2. 기존 PDF의 그림을 그대로 써야 의미가 정확하면 해당 화면이나 부분을 노트북에 넣고 쪽수를 적는다. 새 개념 그림은 [`visual_prompt.md`](templates/visual_prompt.md)의 공통 이미지 생성 틀을 쓰고, 정확한 구조도는 [`flow_diagram.dot`](templates/flow_diagram.dot)의 글꼴·색·여백을 따른다. 그림은 Markdown **attachment**로 넣어 노트북 파일 하나에 포함한다.
3. 그림 바로 아래에 **그림 번호·뜻·볼 지점·표현의 한계**를 적는다. 그림 안의 모호한 글자에 설명을 맡기지 않는다.
4. 설명 직후에는 작은 실행 코드 셀을 둔다. 강사가 실행 결과를 보여 주고 수강생이 무엇이 달라졌는지 말할 수 있어야 한다.
5. CodeMate에 요청할 목표·입출력·제약·검토 기준을 이어서 보여 준다. 수강생은 생성된 코드를 실행하고 리뷰한 뒤 수정 지시를 다시 내려 본다.
6. 블록 마지막에는 확인 질문, 최소 결과물, 빨리 끝낸 수강생의 확장 과제를 둔다.

원본 PDF를 처음에 몰아놓거나 실습 코드를 끝에 몰아놓지 않는다. 각 의미 번호에서 **보여 주기 → 실행 → 실습 → 검토**를 반복한다. 내용과 코드가 안정된 뒤에 VS Code Jupyter Slide Show의 발표용 구획을 다듬는다. HTML은 정적 발표본이며 실제 코드 실행은 VS Code 노트북에서 진행한다. 사용법은 [`NOTEBOOKS.md`](NOTEBOOKS.md)에 적었다.

## 실행과 원본 관리

- 개념과 목표는 원본과 대조하고, 새 실행 경로는 `src/courseware/`의 공통 구현을 사용한다. 원본의 알려진 오류를 그대로 옮기지 않는다. 변경된 구현과 모의 처리 범위를 [자료 대응표](LESSON_SOURCES.md)에 기록한다. 서버·Streamlit처럼 터미널 실행이 자연스러운 코드는 명령과 검토 화면을 노트북에 적는다.
- API 호출·파일 쓰기·메일 발송이 있는 셀은 실행 조건과 예상 결과를 바로 앞에 둔다. 키나 실제 실행 결과는 노트북에 저장하지 않는다.
- PDF 쪽과 코드 파일이 어느 의미 번호에 들어갔는지 기록한다. 중복·생략·순서 변경은 수업 목적과 함께 적어, 원본이 바뀌었을 때 다시 대조할 수 있게 한다.
- `lessons/_template.ipynb`는 한 구간의 셀 배열을 보여 주는 작성용 틀이다. 완성되지 않은 노트북을 수강생 배포본으로 표시하지 않는다.

## 원본과 통합 교안의 차이

- 환경·CodeMate·server/client 기초 설명과 실행 점검을 새로 작성했다. 사내 CodeMate UI 조작은 현장 확인 대상이다.
- Moody’s·Salesforce 사례는 4.2.4에 공식 출처와 수업 적용 해석을 구분해 넣었다.
- 문서 검색은 교육용 가상 자료와 Chroma 메모리 저장소를 사용한다. 실제 문서 접근 정책은 사내에서 별도로 확인한다. RAGaaS는 명시적 모의 호출 예제를 포함한다.
- 기존 메일 발송 예제의 거절 결함을 가져오지 않고, `interrupt`·`Command`로 승인·거절을 구분하는 새 예제를 사용한다. 메일은 발송하지 않는다.
- MCP는 in-memory와 실제 stdio 연결을 실행한다. A2A는 SDK 1.x의 Agent Card·JSON-RPC·Message를 사용한다. 장기 Task·취소는 이번 서버에서 제공하지 않는다.
- Memory 예제는 compile에 Checkpointer와 Store를 함께 연결한다. 캡스톤은 공통 구현에 Supervisor·MCP·승인·Writer·평가·Streamlit을 포함한다.
- `src/raw/`와 `src/solution/`의 기존 파일은 수정하지 않았으며 알려진 결함이 남아 있다. 통합 교안의 검증 결과를 기존 파일 전체에 적용하지 않는다.

원본 PDF 14개를 균등하게 복제하지 않는다. 핵심 이론과 커리큘럼을 유지하며 실행·검토 가능한 예제로 재구성했다. 강사용 배정 합계는 [INSTRUCTOR_TIMING.md](INSTRUCTOR_TIMING.md)에 있다.
