# 통합 교안 조립 지도

최종 교안은 수업에서 바로 여는 **주피터 노트북**이다. 슬라이드를 보여 주고, 그 자리에서 코드를 실행하며, CodeMate 실습과 결과 검토까지 진행한다. 기존 PDF·슬라이드 해설·코드의 순서를 그대로 복제하지 않고 **슬라이드 한 장 또는 몇 장 → 그 자리의 설명 → 관련 코드와 실행 → CodeMate 작업 → 결과 검토**로 내용을 해체해 다시 엮는다.

일차의 진행 순서와 시간 배정은 2026-09-03 커리큘럼 수정본을 기준으로 한다. 강의 직전에는 컨플루언스의 최신 안내와 대조한다.

## 최종 파일 단위

```text
lessons/
  _template.ipynb     한 시간 블록의 화면·실행·실습 셀 배열을 복사할 때 사용
  day01.ipynb          Agent 사고방식 → LLM API → LangChain
  day02.ipynb          RAG → LangGraph → Multi-Agent·Streamlit
  day03.ipynb          복습 → MCP → A2A → LangGraph 심화
  day04.ipynb          Harness → Langfuse → 캡스톤
```

하루 한 권을 수업 시작부터 끝까지 연다. `day01.ipynb`부터 `day04.ipynb`까지는 각 일차 내용이 실제로 조립·검증될 때 만든다. 지금은 작성 틀만 있다. PDF 번호나 기존 `Chapter01`·`Chapter02` 폴더는 **원본 위치**를 찾는 이름이며 통합본의 단위가 아니다.

## 시간표가 우선이다

아래 시간은 **순수 수업 8시간**의 배정이다. 실제 수업은 08:30~17:30이며 점심 1시간이 있다. 점심·휴식의 정확한 시각은 확인되지 않았으므로 시계 시각을 임의로 붙이지 않는다. PDF와 코드는 가져올 재료이며, 한 PDF나 한 Python 파일 전체를 한곳에 붙여 넣으라는 뜻이 아니다.

### 해체 예시: 1일차 LLM·API 180분

아래 분 단위 배치는 **교안 제작 초안**이다. 커리큘럼은 블록 전체에 3시간만 지정한다. 이처럼 PDF 쪽과 코드를 작은 수업 장면으로 나누고, 실제 실행 시간을 보며 조정한다.

| 블록 안의 시간 | 화면·설명 | 바로 이어질 실행·실습 |
| --- | --- | --- |
| 0~25분 | `1-2` 4~7쪽: 학습과 다음 토큰 예측 | 해설 노트북의 작은 토큰 선택 예제 실행·결과 질문 |
| 25~50분 | `1-2` 8~16쪽: 토큰과 컨텍스트 | 메시지 목록을 바꿔 입력 길이와 남길 문맥을 비교 |
| 50~95분 | `1-2` 17~19쪽: 역할과 API 요청 | `01_requests.py`에서 요청 본문을 먼저 조립·검토한 뒤 환경에 맞는 호출 |
| 95~155분 | 같은 슬라이드를 다시 참조: 대화 유지와 스트리밍 | `02_openai.py`의 single-turn·multi-turn·streaming을 분리 실행. 사내 게이트웨이 호환성은 사전 확인 |
| 155~180분 | API 직접 호출과 `get_llm()`의 관계 정리 | `03_langchain.py`·`src/config/llm.py`를 CodeMate와 검토하고 수정 지시 |

한 슬라이드를 여러 실습에서 다시 써도 된다. 위 표의 `01_requests.py`와 `02_openai.py`는 통째로 붙이지 않고 요청 작성·응답 확인·대화 유지·스트리밍을 각 셀로 나눈다.

## 노트북 화면의 흐름

1. Markdown 셀을 **한 화면에 한 핵심 메시지**가 보이도록 나눈다. 제목·그림·간단한 설명이 슬라이드 역할을 한다.
2. 해당 PDF 화면을 Markdown **attachment**로 넣어 노트북 파일 하나에 포함한다. PDF 쪽수를 표시한다. PDF 그림이 복잡하면 필요한 부분을 확대하거나 다시 설명하되, 원본과 의미가 달라지지 않게 한다.
3. 설명 직후에는 작은 실행 코드 셀을 둔다. 강사가 실행 결과를 보여 주고 수강생이 무엇이 달라졌는지 말할 수 있어야 한다.
4. CodeMate에 요청할 목표·입출력·제약·검토 기준을 이어서 보여 준다. 수강생은 생성된 코드를 실행하고 리뷰한 뒤 수정 지시를 다시 내려 본다.
5. 블록 마지막에는 확인 질문, 시간 내 최소 결과물, 빨리 끝낸 수강생의 확장 과제를 둔다.

슬라이드 PDF를 처음에 몰아놓거나 실습 코드를 끝에 몰아놓지 않는다. 각 블록의 시간 배정 안에서 **보여 주기 → 실행 → 실습 → 검토**를 반복한다. 노트북의 슬라이드 메타데이터는 발표 화면으로 넘길 구간에만 붙인다. 발표 화면에 맞추기 위해 코드 실행의 순서를 깨지 않는다.

## 실행과 원본 관리

- 강의용 코드만 실행 셀로 옮기되, 원본 `src/raw/`와 `src/solution/`의 정답에 맞춘다. 서버·Streamlit처럼 터미널 실행이 자연스러운 코드는 명령과 검토 화면을 노트북에 적는다.
- API 호출·파일 쓰기·메일 발송이 있는 셀은 실행 조건과 예상 결과를 바로 앞에 둔다. 키나 실제 실행 결과는 노트북에 저장하지 않는다.
- PDF 쪽과 코드 파일이 어느 시간 블록으로 들어갔는지 기록한다. 중복·생략·순서 변경은 수업 목적과 함께 적어, 원본이 바뀌었을 때 다시 대조할 수 있게 한다.
- `lessons/_template.ipynb`는 한 구간의 셀 배열을 보여 주는 작성용 틀이다. 완성되지 않은 노트북을 수강생 배포본으로 표시하지 않는다.

## 원본과 커리큘럼의 차이

- 1일차 개발 환경·CodeMate 설정과 3일차 server/client 기초는 기존 PDF만으로 수업을 채울 수 없다. 설명과 확인 실습을 통합 교안에 새로 작성해야 한다.
- 4일차 Moody's·Salesforce 사례는 `4-2` PDF에 별도 설명이 없다. 최신 강의 자료로 사례 범위와 출처를 확인해 보완해야 한다.
- 2일차 RAG 실습의 로컬 PDF·Chroma와 사내 문서 접근 제약, 4일차 캡스톤의 웹검색·파일시스템 접근 제약은 실제 강의장 정책에 맞춰 실행 경로를 확정해야 한다. 사외 준비에서는 RAGaaS 모의 응답임을 분명히 표시한다.
- `src/raw/Chapter01/04-langgraph/04_human_in_the_loop.py`는 거부 분기에서 실제 메일이 발송되는 알려진 결함이 있다. 이 동작을 고치고 확인하기 전에는 통합 교안의 실행 셀로 옮기지 않는다.

각 일차의 배정 합계는 8시간, 전체는 32시간이다. PDF 14개를 균등하게 배분하지 않는다. 강의 목표와 시간에 필요한 부분을 선택하고, 생략한 재료는 기록한다.
