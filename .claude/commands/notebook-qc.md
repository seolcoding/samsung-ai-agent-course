# /notebook-qc

**목적:** `course/Chapter*/notebooks/` 교안 노트북(수강생본)이 지금까지 정한 QC 기준을 지키는지 확인한다. 고치지 않고 보고만 한다.

노트북은 두 종류이고, 파일 이름 끝으로 구분한다.
- **강의** `*_LEC.ipynb`: 슬라이드(`show_slides`) + 설명 + 퀴즈. 실습 코드 도구는 없다.
- **실습** `*_LAB.ipynb`: `dev/builders/build_lab.py`가 `dev/builders/labs/<폴더>.json`과 원본 코드로 조립한다. 원본 파일마다 준비 코드(접힘) → 구획마다 예제(완성 코드 실행, `# ✍️ CHANGE_HERE:` 줄의 값만 바꿔 보기 → 🟢/⛔ 성공 기준) 또는 과제(설명 → 프롬프트 힌트(3문장 이내) → 🟢/⛔ 성공 기준 → `# ✍️ WRITE_HERE:` 아래 빈칸(`...  # ✍️ …`) 셀 → 정답 보기(접힘)). 성공 기준은 자동 검사하지 않고 수강생이 스스로 판단한다. TODO가 없는 파일은 끝에 "AI에게 물어보기"(프롬프트 힌트 + 성공 기준). 제목 옆 표시는 `(예제)`·`(과제)`이고, ✍️ 표시 주석은 대상 줄 바로 위에 같은 들여쓰기로 한 줄을 차지한다. 수강생 글에서는 CodeMate 대신 "AI"라고 쓴다. 지시문 완성본은 주지 않는다. 실행되지 않는 참고 코드는 "참고:" 절의 ```` ```python ```` 블록.

수강생은 노트북만 받는다(.py 파일은 보이지 않는다). 노트북 하나로 완결되어야 한다.

**인자:** `$ARGUMENTS` = 노트북 경로. 비어 있으면 `course/Chapter*/notebooks/*.ipynb` 전부.
사용자가 "실행"·"execute"를 말하면 새 커널 실행까지 한다.

## 1단계: 하네스 실행 (규칙으로 판정되는 것)

```
uv run python dev/qc/notebook_qc.py $ARGUMENTS
uv run --extra notebooks python dev/qc/notebook_qc.py $ARGUMENTS --execute   # 실행을 요청받았을 때
```

- 하네스가 보는 것
  - 공통: 번호 제목·`<small>` 표시·목차, 강사용 상자, 숨긴 도구 셀(`show_*`·`slide_setup`·환경 점검·`sys.path` 셀), 출력 없음, 외부 주소 없음(실습의 원본 코드는 제외), (pN) 없음, provider 단어, 합니다체(WARN), 반복(WARN), 퀴즈 규칙.
  - 공통(수강생 글 = `<details>` 밖 마크다운 + 퀴즈 글): `CodeMate` 언급은 FAIL("AI"라고 쓴다), `○○.py`·`src/`·`lessons/`·`.ipynb` 언급은 FAIL, "강의 노트북"·"실습 노트북"·"강의에서 본"·`_LEC`·`_LAB`은 WARN. 강사용 상자는 제외.
  - 강의: `run_step`·`show_code`·`show_code_map`·`make_blank`·`show_diff`가 있으면 FAIL. `slide_setup()` 뒤 `show_slides` 필수. 예측 셀 말고는 코드 셀을 숨김.
  - 실습: `make_blank`·`run_step`·`show_diff`·`show_code_map`·`show_slides`가 있으면 FAIL. `**CodeMate 지시문**`이 있으면 FAIL, `✍️ CHANGE_HERE`·`WRITE_HERE`가 코드 줄 끝에 붙어 있으면 FAIL, `**프롬프트 힌트**`가 3문장을 넘으면 FAIL, 보이는 코드에 `TODO`가 남았거나 `WRITE_HERE`·`CHANGE_HERE` 앞에 `# ✍️`가 없으면 FAIL, `show_criteria` 자동 검사 셀이 있으면 FAIL. 예제의 CHANGE_HERE는 같은 장에 🟢 성공 기준 글. 과제 빈칸 셀마다 ① 보이고 빈칸 상태 그대로 문법에 맞음 ② 같은 절 앞쪽에 `**프롬프트 힌트**`와 🟢 항목이 있는 `**성공 기준**` ③ 다음 제목 전에 `정답 보기` 상자가 있고, 그 ```` ```python ```` 블록을 빈칸에 차례로 끼우면 문법에 맞음. 원본 파일 절의 첫 코드(준비 코드)가 보이면 WARN. `(작성 예정)`은 뼈대 상태라 WARN.
- 결과의 FAIL/WARN과 셀 번호(0부터)를 그대로 가져온다. 실행본은 `~/000_Inbox/080_Temporary/notebook_qc/`에 생긴다.
- 키 값이 출력에 나왔다는 결과가 있어도 값을 옮겨 적지 않는다. 셀 번호만 적는다.

## 2단계: 판단 점검표 (노트북을 직접 읽고 본다)

노트북, 퀴즈 JSON(`course/ChapterNN/assets/quizzes/<권>/`), 원본(`course/ChapterNN/code/raw/`, `course/ChapterNN/slides/` PDF)을 대조한다. 실습은 `course/ChapterNN/code/solution/`(정답 보기와 대조)과 `lessons/drafts/labs/<폴더>.json`도 본다.

**공통**

1. **내용 유지:** 내용·순서·실습 코드는 원본 그대로이고, 전달 방식만 바뀌었다. 새 예제·새 과제 코드가 없다.
2. **설명 수준 C:** 슬라이드 요약 + 코드 연결. "왜 배우나"는 할 말이 있는 곳에만 있다.
3. **인지부하 최소화:** 설정·provider 분기·사내 미확인 사항은 "강사용 메모" 상자에 숨겼다. 수강생 글에 없다.
4. **퀴즈 모양:** 4지선다, 선택지 같은 크기, 슬라이드 색(`show_quiz`로 표시).
5. **예측 퀴즈 위치:** 답이 나오는 슬라이드보다 앞에 있다.
6. **숫자 정답:** 실행 출력의 숫자를 정답으로 고정하지 않는다. 숫자 정답은 코드로 계산한다.
7. **쪽 인용:** "(p6)" 같은 괄호 인용은 금지. 문장 안 언급("p9에 적힌")은 허용하되 어색하지 않은지 본다.
8. **기계적 반복 금지:** 같은 문장, 같은 피드백 서두, 중복 머리글이 되풀이되지 않는다.
9. **강의 용어:** 출력하다(찍다 X), 답변 텍스트(답 글자 X), 호출하다(부르다 X), 이 노트북(이 권 X).
10. **문체:** 수강생 글은 합니다체다.
11. **구조:** 번호 목차가 맨 위에 있고, 제목 옆에 (슬라이드)(퀴즈)(코드)(예제)(과제) 표시가 내용과 맞다.
12. **슬라이드:** PDF.js로 그린다. 외부 CDN·외부 주소가 없다.
13. **원본 보호:** `course/*/code/`가 바뀌지 않았다 (`git status course/*/code`로 확인). 수강생본에 강사용 메모가 없고 강사본(`dev/instructor/`)에만 있다.
14. **실행:** 새 커널에서 오류 0, 키 값이 출력되지 않는다.
15. **커밋 전:** 노트북 출력과 실행 번호를 비웠다.
16. **노트북 하나로 완결:** 수강생 글이 다른 노트북("강의에서 본", "실습 노트북에서")이나 다른 파일을 언급하지 않는다. 이 노트북만 열어도 따라갈 수 있다.
17. **수강생은 노트북만 받는다:** `.py` 파일 이름, `src/`·`lessons/` 같은 경로, 줄 번호("30~54줄")를 수강생 글·지시문·퀴즈에 쓰지 않는다. 코드는 "위 셀", "이 셀의 빈칸"처럼 노트북 안에서 가리킨다.

**강의 노트북만**

18. **실습 코드 없음:** 코드를 실행·빈칸·비교하는 셀이 없다. 코드 이야기는 슬라이드·설명으로만 한다.

**실습 노트북만**

19. **지시문 완성본 대신 프롬프트 힌트:** 힌트는 3문장 이내로 "무엇을 넣고, 무엇을 받고, 무엇을 하지 말지"를 알려 준다. 정답 코드를 그대로 불러 주지 않는다. 힌트만 받은 모델에게 시켜 보면 정답과 같은 일을 하는 코드가 나온다(점검은 가벼운 모델, 예: Sonnet 서브에이전트).
20. **표시와 가독성:** 원본 코드의 들여쓰기·줄은 그대로이고, `# ✍️ CHANGE_HERE:`·`# ✍️ WRITE_HERE:` 주석만 대상 줄 바로 위에 같은 들여쓰기로 더했다. CHANGE_HERE는 바꿔 볼 값 하나만 가리킨다. 빈칸 셀과 원본의 차이는 ✍️ 줄뿐이다.
21. **성공 기준 → 정답 보기:** 성공 기준이 🟢(되어야 하는 것)·⛔(다시 할 신호)로 적혀 있고, 실행 화면만 보고 수강생이 판단할 수 있는 말이다(코드 내부 값이 아니라 보이는 결과). 그다음 접힌 "정답 보기"로 비교한다. 정답 보기가 `src/solution/`과 맞는다.
22. **TODO 하나 = 작은 목표 하나:** 빈칸 하나가 한 가지 작은 목표만 다룬다. 한 지시문에 여러 일을 몰아넣지 않는다.
23. **참고 코드:** 원본에서 실행되지 않는 코드는 "참고:" 절의 ```` ```python ```` 블록으로만 보이고, 실행 셀로 만들지 않는다.

## 3단계: 보고 (한국어, 짧게)

```
## QC 결과: <노트북>
하네스: PASS n · WARN n · FAIL n (실행 여부)

### FAIL
- 셀 N: 무엇이 문제인지 — 고치는 방법
### WARN
- 셀 N: … — …
### 판단 점검표
- 항목 번호: 문제 있음/없음 — 근거(셀 번호), 고치는 방법
```

- 사용자가 고치라고 하기 전에는 파일을 고치지 않는다.
- 노트북을 고칠 때는 빌더(`dev/builders/build_*.py`)와 `dev/builders/*.json`, `dev/builders/labs/*.json`을 고치고 다시 조립한다. 노트북을 직접 고치지 않는다.
