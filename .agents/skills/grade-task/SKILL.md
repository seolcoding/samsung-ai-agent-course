# 과제 채점

수강생은 코딩이 낯선 사람이 많다. 쉬운 말로 짧게, 결과부터 말한다.

## 순서

1. **무엇을 채점할지 정하기.** 챗봇 단계면("챗봇 3단계", 열린 파일 `chatbot/stage3.py`) 기준 파일은 `references/chatbot-3.md`, 실습별 과제면("1-2 과제", 열린 파일 `tasks/1-2/task.py`) `references/1-2.md`다. 모르면 한 번만 묻는다.
2. **기준 읽기.** 이 스킬 폴더의 그 기준 파일을 읽는다. 과제 파일 경로, 실행 명령, 학습 목표(= 채점 기준)와 확인 방법, 확인 질문이 있다. 기준 파일이 없으면 "이 과제의 채점 기준이 없습니다"라고 말하고 멈춘다.
3. **과제 파일 읽기.** 시작 상태 그대로면(이번 단계의 빈 자리가 그대로 남아 있음) 채점하지 않는다. 그 폴더의 README.md대로 AI와 먼저 작성하라고 안내한다.
4. **실행하기.** 저장소 맨 위 폴더에서 기준 파일의 실행 명령을 터미널로 돌린다. 모델을 호출하므로 수십 초 걸릴 수 있다고 먼저 알린다. 챗봇(Streamlit)은 기준 파일의 확인 명령(`scripts/check_streamlit.py`)으로 화면 없이 확인한다(브라우저를 띄우지 않는다).
5. **판정하기.** 학습 목표(기준)마다 "확인" 줄대로 실행 출력과 코드를 보고 판정한다. "확인" 줄이 코드를 보라고 하면 코드로 판정한다(그래도 실행은 반드시 한 번 한다). 모델의 답은 실행마다 말이 달라지므로, 문구가 달라도 기준의 뜻을 만족하면 🟢이다.
   - 🟢 통과: 출력이나 코드에서 직접 확인했다.
   - ⛔ 수정 필요: 실행했는데 기준과 다르다. 무엇이 다른지 한 줄로 적는다.
   - ❔ 확인 불가: 실행하지 못했다(오류, 설정 문제, 시간 초과). 그 기준은 통과로 치지 않는다.
6. **보고하기.** 아래 형식으로 보고한다.
7. **확인 질문.** 기준 파일의 확인 질문을 보기 4개와 함께 내고, 정답은 말하지 않는다. 수강생이 답하면 맞았는지와 해설을 알려 준다.

수강생이 다른 경로의 파일을 채점해 달라고 하면, 기준 파일의 실행 명령에서 파일 경로만 바꿔 실행한다.

## 보고 형식

```
과제 채점: <번호> — 통과 / 수정 필요 / 확인 불가 (<N>개 중 <M>개 통과)
- 🟢 <기준>
- ⛔ <기준>: <무엇이 다른지>
- ❔ <기준>: <왜 확인하지 못했는지>
다음 할 일: <하나만. AI에게 어떻게 다시 지시하면 되는지 한 문장>

확인 질문: <질문>
 1) … 2) … 3) … 4) …
```

- 전부 🟢이면 "통과", 하나라도 ⛔이면 "수정 필요", ⛔ 없이 ❔가 있으면 "확인 불가"다.
- 다음 할 일은 가장 먼저 고칠 것 하나만 준다. 전부 통과면 "다음 장으로 넘어갑니다"라고 쓴다.

## 실행이 안 될 때

- 오류 메시지가 설정 문제(키·주소·패키지·`환경변수가 필요합니다`·연결 오류)로 보이면, 저장소 맨 위에서 `uv run python -m config.check --json`을 실행해 ⛔ 항목을 찾는다. 이때 기준은 모두 ❔로 두고, `fix` 안내대로 고칠 곳을 알려 준다.
- 코드 오류면 오류의 원인을 쉬운 말로 설명하고, 다음 할 일로 무엇을 고쳐 달라고 지시하면 되는지 적는다.

## 하지 않는 것

- 실행하지 않고 통과라고 하지 않는다. 코드만 보고 "될 것 같다"고 판정하지 않는다.
- 채점하는 동안 과제 파일을 고치지 않는다. 고쳐 달라는 말을 들은 뒤에만 고친다. 고칠 때도 과제 파일만 고치고, 필요한 만큼만 고친다.
- 정답 코드를 통째로 써 주지 않는다. 현재 단계 설명 → 작은 힌트 → 필요한 수정 순서로 돕는다.
- `.env`의 키·토큰 값을 출력하거나, 수강생에게 키나 사내 데이터를 대화에 붙여 넣으라고 하지 않는다.
- 수업에서 쓰는 방식을 바꾸지 않는다. 모델은 `config.llm.get_llm()`, 임베딩은 `config.embeddings.get_embeddings()`로 부르고, 다른 라이브러리·모델로 바꾸지 않는다.
- 과제 범위를 넘는 기능을 더하라고 하지 않는다.
