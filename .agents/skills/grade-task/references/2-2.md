# 2-2 과제: 기획자와 검토자 두 Agent

빌드 산출물이다(dev/builders/build_lab.py). 직접 고치지 않는다.

- 과제 파일: `course/Chapter01/notebooks/2-2_task.py`
- 실행 명령(저장소 맨 위에서): `uv run --env-file .env python course/Chapter01/notebooks/2-2_task.py`

## 목표

기획자(planner)가 행사 계획을 쓰고 검토자(reviewer)가 "승인" 또는 "수정"을 판단하는 두 Agent 그래프를 만듭니다. 수정이면 기획자에게 돌아가고, 승인이거나 두 번 고쳤으면 끝냅니다.

## 들어갈 것

- State에 `messages`, `plan`(계획), `review`(검토 의견), `rounds`(고친 횟수)를 둡니다
- planner 노드는 계획을 3줄로 쓰고(검토 의견이 있으면 반영), reviewer 노드는 "승인" 또는 "수정: 이유"로 답합니다
- reviewer 뒤의 갈림길 함수는 반환 타입 `Literal["planner", "__end__"]`을 달고 `add_conditional_edges`로 잇습니다. "수정"이면 planner로 돌아가고, 승인이거나 이미 2번 고쳤으면 끝냅니다(planner는 처음 1번 + 고치기 최대 2번)
- 주제 하나(예: 신입사원 환영 행사)로 실행하고 단계마다 누가 무엇을 썼는지와 최종 계획을 출력합니다

## 성공 기준과 확인 방법

1. 🟢 출력에 planner와 reviewer의 차례가 순서대로 보인다
   - 확인: 출력에 planner 계획 → reviewer 판단 순서가 한 번 이상 있다
2. 🟢 검토가 "수정"이면 planner로 돌아가고, 고친 횟수는 2번을 넘지 않는다
   - 확인: 코드의 갈림길 함수가 "수정"이면 planner, 승인이거나 `rounds`가 2 이상이면 끝으로 보낸다. 출력에서 reviewer가 "수정"이라고 한 뒤 planner가 다시 나오고(고칠 횟수가 남았을 때), planner는 3번을 넘지 않는다
3. 🟢 마지막에 마지막 planner가 쓴 최종 계획이 출력된다
   - 확인: 출력 끝의 최종 계획이 마지막 planner 단계에서 쓴 계획과 같다

## 확인 질문

검토자가 계속 "수정"만 답하면 그래프는 어떻게 되나요?

1. LangGraph가 알아서 한 번 돌고 멈춘다
2. 검토자가 자동으로 승인으로 바뀐다
3. 멈추는 조건이 없으면 반복 한도(recursion limit)에 걸려 오류가 난다
4. 기획자 노드가 건너뛰어진다

정답: 3

해설:
- 1: 알아서 멈추지 않습니다. 멈추는 조건은 직접 짭니다.
- 2: 검토자의 답은 모델이 정합니다. 저절로 바뀌지 않습니다.
- 3: 멈추는 조건이 없으면 `GraphRecursionError`가 납니다. 그래서 고친 횟수로 끝내는 조건을 둡니다.
- 4: 갈림길이 planner로 보내므로 건너뛰지 않습니다.
