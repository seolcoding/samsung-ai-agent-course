# 3-4 과제: 그래프 나누고 기억하기

- 과제 파일: `course/Chapter02/tasks/3-4/3-4_task.py`
- 실행 명령(저장소 맨 위에서): `uv run --env-file .env python course/Chapter02/tasks/3-4/3-4_task.py`
- 시작 상태: `=== 목표 N ===` 아래에 `(아직 작성하지 않았습니다)`가 출력되는 목표는 아직 작성하지 않은 것이다. 네 목표 모두 그대로면 채점하지 않는다. 일부만 그대로면 그 목표는 ⛔(아직 작성하지 않음)로 둔다.
- 모델을 일곱 번쯤 부르고 약 15초 걸린다(사외 OpenAI 기준). 파일을 만들지 않는다(`.db` 파일이 생기면 목표 3의 ⛔ 사유로 적는다).

## 학습 목표와 확인 방법

1. 따로 compile한 서브그래프를 부모 노드에서 호출해 결과를 부모 State로 넘길 수 있다
   - 확인: `=== 목표 1: 서브그래프 ===` 아래에 `DOCUMENT`의 내용(인공지능·LLM·텍스트 생성 등)을 요약한 문장이 부모 State의 `summary`로 출력된다. 코드에 서브그래프용 State와 부모 State가 따로 있고, 서브그래프를 `.compile()`한 뒤 **부모 그래프의 노드 함수 안에서** `summary_subgraph.invoke(...)`를 불러 그 결과를 `{"summary": ...}`로 돌려준다(노드가 `add_node("이름", summary_subgraph)`로 서브그래프를 그대로 넣은 것도 🟢). 서브그래프 없이 부모 노드에서 `llm.invoke`로 바로 요약하면 ⛔, 서브그래프를 부모 그래프 밖에서 따로 `invoke`하고 결과만 출력하면 ⛔
2. fan-out/fan-in으로 두 작업을 동시에 실행하고 `Annotated` 리듀서로 모을 수 있다
   - 확인: `draw_ascii()` 그림에서 `__start__`에서 `pros`·`cons` 두 갈래가 나가 `merge`로 모인다. 출력의 `notes`에 `장점:` 줄과 `단점:` 줄이 하나씩(모두 2개) 있다. 코드에 `add_edge(START, "pros")`, `add_edge(START, "cons")`, `add_edge("pros", "merge")`, `add_edge("cons", "merge")`가 있고, `notes`가 `Annotated[list..., operator.add]`(또는 두 목록을 이어 붙이는 함수)로 선언되어 있다. `pros` → `cons`처럼 차례로 이었으면 ⛔. 리듀서 없이 `notes: list[str]`이면 실행할 때 `InvalidUpdateError`가 나므로 ⛔
3. `MemorySaver`와 `thread_id`로 같은 thread는 이어 가고 다른 thread는 모르는 것을 `get_state` 메시지 수로 보일 수 있다
   - 확인: `thread_a`의 두 번째 답이 "홍길동"을 말하고, `thread_b`의 답은 이름을 모른다고 한다. `get_state`로 출력한 메시지 수가 `thread_a` 4, `thread_b` 2다. 코드에 `compile(checkpointer=MemorySaver())`가 있고 두 thread의 config는 `thread_id`만 다르며, 메시지 수를 `get_state(config).values["messages"]`의 길이로 센다. 메시지 수를 직접 숫자로 써 넣었거나, 두 thread가 같은 `thread_id`를 써서 수가 같으면 ⛔
4. `InMemoryStore` namespace에 사용자 정보를 `put`하고 새 thread에서 `search`로 꺼내 쓸 수 있다
   - 확인: `session_2`의 답(마지막 `Ai Message`)에 "이지수"와 "피아노"가 나오고, `session_2`의 메시지 수가 2다(처음 쓰는 thread라 체크포인터에는 앞 대화가 없다). 코드에 `store.put(("memories", USER_ID), ..., {...USER_INFO...})`가 있고, 노드가 `store.search(("memories", ...))`의 결과를 시스템 메시지에 넣으며, `compile(checkpointer=MemorySaver(), store=store)`로 컴파일한다(노드가 `store: BaseStore` 인자로 받아 써도 🟢). 사용자 정보를 시스템 메시지에 문자열로 바로 써 넣고 `search`를 안 쓰면 ⛔, 같은 thread에서 이름을 먼저 말해 체크포인터로 답하게 했으면 ⛔(새 thread의 메시지 수가 2보다 크다)

## 확인 질문

목표 4에서 `session_2`는 처음 쓰는 thread인데도 이름과 취미를 알았습니다. 무엇 덕분인가요?

1. `MemorySaver`가 모든 thread의 대화를 하나로 합쳐 두기 때문
2. 노드가 thread와 관계없는 Store의 `("memories", USER_ID)` namespace에서 사용자 정보를 `search`해 시스템 메시지에 넣었기 때문
3. 목표 3에서 `thread_a`에 이름을 말해 두었기 때문
4. LLM이 앞 호출에서 들은 정보를 스스로 기억하기 때문

정답: 2

해설:
- 1: 체크포인터는 `thread_id`마다 따로 저장합니다. 목표 3에서 `thread_b`가 이름을 몰랐던 것이 그 증거입니다.
- 2: Store는 thread를 넘어 공유되는 장기 기억입니다. namespace(여기서는 사용자)로 나눠 두고, 어느 thread에서든 `search`로 꺼내 쓸 수 있습니다.
- 3: `thread_a`는 다른 그래프(`chat_graph`)의 다른 thread이고, 말한 이름도 홍길동입니다. `session_2`의 메시지 수가 2인 것도 앞 대화가 없다는 뜻입니다.
- 4: 모델은 호출마다 받은 메시지만 봅니다. 기억은 그래프가 메시지에 넣어 줘야 합니다.
