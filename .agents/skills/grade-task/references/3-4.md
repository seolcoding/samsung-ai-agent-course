# 3-4 과제: 대화를 이어 가는 장단점 정리 그래프

빌드 산출물이다(dev/builders/build_lab.py). 직접 고치지 않는다.

- 과제 파일: `course/Chapter02/notebooks/3-4_task.py`
- 실행 명령(저장소 맨 위에서): `uv run --env-file .env python course/Chapter02/notebooks/3-4_task.py`

## 목표

장점 노드와 단점 노드가 동시에 실행되고(fan-out) 정리 노드에서 합쳐지는(fan-in) 그래프를 만듭니다. 그래프에 `MemorySaver` 체크포인터를 붙여, 같은 `thread_id`로 보낸 두 번째 질문이 첫 질문의 주제를 이어받게 합니다.

## 들어갈 것

- State는 `messages`(`add_messages`)와 `pros`, `cons` 세 키입니다. `pros` 노드와 `cons` 노드는 대화 메시지 전체를 LLM에 넘겨 마지막 질문 주제의 장점·단점을 두 줄로 받고, 자기 키만 돌려줍니다
- `merge` 노드는 LLM을 부르지 않고 `pros`와 `cons`를 "장점: …", "단점: …" 모양의 `AIMessage` 하나로 묶어 `messages`로 돌려줍니다
- START → `pros`, START → `cons`, `pros` → `merge`, `cons` → `merge`, `merge` → END로 잇고, `compile(checkpointer=MemorySaver())`로 컴파일한 뒤 `print(app.get_graph().draw_ascii())`로 그래프 모양을 출력합니다
- 같은 `config = {"configurable": {"thread_id": "user-1"}}`로 "재택근무의 장점과 단점을 알려줘"와 "그 주제를 팀장 입장에서 다시 정리해줘"를 차례로 실행합니다. 결과는 `results = pros_cons_result["messages"]`처럼 꺼내 `for m in results: m.pretty_print()`로 출력합니다

## 성공 기준과 확인 방법

1. 🟢 그래프 그림에 `pros`와 `cons`가 나란히 있고, 둘 다 `merge`로 모인다
   - 확인: `draw_ascii()` 출력에 `__start__`에서 `pros`·`cons` 두 갈래가 나가 `merge`로 모이고 `__end__`로 끝난다. 코드에 `add_edge(START, "pros")`, `add_edge(START, "cons")`, `add_edge("pros", "merge")`, `add_edge("cons", "merge")`가 있다(`pros` → `cons`처럼 차례로 이으면 수정 필요)
2. 🟢 두 질문 모두 마지막 `Ai Message`에 `장점:`과 `단점:`이 함께 나온다
   - 확인: 질문마다 마지막 `Ai Message` 칸에 `장점:`과 `단점:` 줄이 모두 있고 둘 다 비어 있지 않다
3. 🟢 두 번째 질문의 출력에 첫 질문과 그 답까지 메시지 네 개가 보이고, 답이 재택근무 이야기를 이어 간다
   - 확인: 두 번째 실행의 `pretty_print()` 출력에 `Human Message` 2개와 `Ai Message` 2개가 있고, 두 번째 답이 질문에 없던 재택근무를 다룬다. 코드에 `compile(checkpointer=MemorySaver())`가 있고 두 `invoke`가 같은 `thread_id`의 config를 쓴다

## 확인 질문

두 번째 질문에는 주제를 적지 않았는데도 답이 재택근무 이야기를 이어 갔습니다. 무엇 덕분인가요?

1. `pros`와 `cons`를 동시에 실행했기 때문
2. LLM이 앞 호출을 스스로 기억하기 때문
3. 체크포인터가 같은 `thread_id`의 앞 메시지를 저장해 두었다가 이어 주기 때문
4. `merge` 노드가 두 결과를 하나로 합쳤기 때문

정답: 3

해설:
- 1: 동시 실행은 시간을 줄일 뿐, 앞 대화를 남기지 않습니다.
- 2: 모델은 호출마다 받은 메시지만 봅니다. 앞 대화는 그래프가 넘겨 줘야 합니다.
- 3: 같은 `thread_id`로 부르면 체크포인터에 저장된 앞 메시지가 State에 이어지고, 노드가 그 메시지를 모두 LLM에 넘깁니다.
- 4: `merge`는 이번 질문의 장점·단점을 묶을 뿐입니다. 앞 질문의 메시지를 가져오지 않습니다.
