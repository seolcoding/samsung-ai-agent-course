# 4-2 과제: 기록과 점수가 남는 질문 답변기

빌드 산출물이다(dev/builders/build_lab.py). 직접 고치지 않는다.

- 과제 파일: `course/Chapter02/notebooks/4-2_task.py`
- 실행 명령(저장소 맨 위에서): `uv run --env-file .env python course/Chapter02/notebooks/4-2_task.py`

## 목표

질문에 답하는 체인 실행을 `@observe` 함수로 묶어 Langfuse에 trace 하나로 기록하고, 그 trace에 규칙 점수와 LLM 채점 점수를 하나씩 남깁니다. 질문 두 개를 실행하고, 질문마다 trace ID와 두 점수를 출력합니다.

## 들어갈 것

- 질문에 3문장 이내로 답하는 체인(프롬프트 → `llm` → `StrOutputParser()`)을 만듭니다. 기록 도구 `handler = CallbackHandler()`는 함수 밖에서 한 번 만듭니다
- `@observe(name="qa-task")`를 붙인 함수가 질문 하나를 받아 체인을 `config={"callbacks": [handler]}`로 실행하고 답을 돌려줍니다. 함수를 호출한 뒤 `handler.last_trace_id`를 `trace id: …`로 출력합니다
- 규칙 점수 `short-answer`(답이 200자 이하면 1.0, 아니면 0.0)와 LLM 채점 점수 `llm-judge`("질문에 직접 답했는가"를 0.0~1.0 숫자 하나로)를 `langfuse.create_score`로 그 trace ID에 남기고, 두 점수를 출력합니다
- 질문 `Langfuse의 Trace가 뭐야?`와 `RAG를 한 문장으로 설명해줘`를 차례로 실행하고, 파일 맨 끝에서 `langfuse.flush()`를 호출합니다

## 성공 기준과 확인 방법

1. 🟢 질문마다 답과 `trace id:` 줄이 출력되고, 두 질문의 trace ID가 서로 다르다
   - 확인: 출력에 질문마다 답과 `trace id:` 줄이 있고, 값이 `None`이 아닌 32자리 16진수이며 두 값이 다르다
2. 🟢 질문마다 `short-answer`와 `llm-judge` 점수가 0.0~1.0 숫자로 출력된다
   - 확인: 출력에 질문마다 두 점수 이름과 0.0~1.0 숫자가 있고, `short-answer` 값이 그 답의 길이(200자 기준)와 맞는다. 코드에서 `create_score`가 `trace_id`와 함께 두 이름으로 호출된다
3. 🟢 Langfuse에 `qa-task` trace가 질문마다 생기고, 각 trace에 점수 두 개가 붙는다
   - 확인: 코드에 `@observe(name="qa-task")`, 체인 실행의 `config={"callbacks": [handler]}`, 파일 끝의 `langfuse.flush()`가 있다. 실행이 끝난 뒤, 출력된 trace ID마다 저장소 맨 위에서 `uv run --env-file .env python -c "from langfuse import get_client; a = get_client().api; t = '<trace id>'; print([o.name for o in a.observations.get_many(trace_id=t, is_root_observation=True).data], sorted(s.name for s in a.scores_v3.get_many_v3(trace_id=t).data))"`를 실행한다. `['qa-task'] ['llm-judge', 'short-answer']`가 나오면 🟢, 맨 앞 이름이 `qa-task`가 아니거나 점수 이름이 빠졌으면 ⛔. 점수는 1분쯤 늦게 보일 수 있으니, 목록이 비어 있으면 30초 간격으로 두 번 더 조회한다. 조회가 오류(연결·권한, 이 주소가 없는 Langfuse 버전)로 안 되거나 다시 조회해도 비어 있으면 ❔로 두고 이유를 적는다

## 확인 질문

`langfuse.create_score`로 점수를 남길 때 `trace_id`를 함께 넘기는 까닭은?

1. 점수를 더 빨리 서버로 보내려고
2. trace_id가 없으면 점수가 0으로 기록되어서
3. 점수를 어느 실행 기록(trace)에 붙일지 정하려고
4. LLM이 trace를 읽고 점수를 계산하게 하려고

정답: 3

해설:
- 1: 보내는 속도와는 관계가 없습니다. 모아 둔 기록을 바로 보내는 것은 `flush()`입니다.
- 2: 점수 값은 코드가 넘긴 숫자 그대로입니다. trace_id는 붙일 곳을 정합니다.
- 3: trace ID로 점수가 붙을 trace를 정합니다. 그래서 화면에서 그 답의 실행 기록과 점수를 함께 봅니다.
- 4: 점수는 코드나 Judge가 미리 계산해 넘깁니다. `create_score`는 계산하지 않습니다.
