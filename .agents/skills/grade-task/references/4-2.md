# 4-2 과제: 기록과 점수가 남는 Agent

- 과제 파일: `course/Chapter02/tasks/4-2/4-2_task.py`
- 실행 명령(저장소 맨 위에서): `uv run --env-file .env python course/Chapter02/tasks/4-2/4-2_task.py`
- 기록 조회 명령(실행이 끝난 뒤, 출력의 trace ID 세 개를 목표 1·2·4 순서로 넣는다):

```
uv run --env-file .env python -c "import sys; from langfuse import get_client; a = get_client().api; [print(t, sorted((o.name, {p.id: p.name for p in obs}.get(o.parent_observation_id, '-')) for o in obs), sorted(s.name for s in a.scores_v3.get_many_v3(trace_id=t).data)) for t in sys.argv[1:] for obs in [a.observations.get_many(trace_id=t, limit=100).data]]" <목표1 ID> <목표2 ID> <목표4 ID>
```

  trace마다 `(이름, 부모 이름)` 목록(부모가 없는 맨 위는 `'-'`)과 점수 이름 목록이 한 줄로 나온다. 기록은 몇 초~1분 늦게 보일 수 있으니, 목록이 비어 있으면 30초 간격으로 두 번 더 조회한다. 조회가 오류(연결·권한, 이 주소가 없는 Langfuse 버전)로 안 되거나 다시 조회해도 비어 있으면, 조회로 판정하는 부분은 ❔로 두고 이유를 적는다. 출력·코드로 판정하는 부분을 먼저 본다.

## 학습 목표(채점 기준)

1. `CallbackHandler`를 config로 넘겨 체인 실행을 trace로 기록하고 trace ID를 출력할 수 있다
   - 확인: `=== 목표 1 ===` 아래에 답과 `trace id:` 줄이 있고, 값이 `None`이 아닌 32자리 16진수다. 코드에서 `CallbackHandler()`를 만들어 `chain.invoke(..., config={"callbacks": [handler]})`로 넘긴다. 조회 결과 이 trace의 맨 위가 `('RunnableSequence', '-')`이고 그 아래에 `ChatOpenAI`(사내는 그 모델 클래스 이름)가 있으면 🟢. 출력·코드가 맞는데 조회만 안 되면 ❔
2. `@observe(name=...)`로 일반 함수를 한 trace 아래 중첩 span으로 기록할 수 있다
   - 확인: `=== 목표 2 ===` 아래에 답과 `trace id:` 줄이 있고, 목표 1의 ID와 다르다(같으면 바깥 함수 안의 `chain.invoke`에 핸들러를 안 넘긴 것이다 → ⛔). 코드에서 서로 다른 이름의 `@observe(name=...)` 함수 두 개가 있고 바깥 함수가 안쪽 함수와 `chain.invoke`를 부른다. 조회 결과 맨 위가 바깥 함수 이름(`(<바깥 이름>, '-')`)이고, 안쪽 함수 이름과 `RunnableSequence`의 부모가 둘 다 바깥 함수 이름이면 🟢. 안쪽 함수 이름이 목록에 없거나 부모가 다르면 ⛔. 출력·코드가 맞는데 조회만 안 되면 ❔
3. 규칙 점수와 LLM 채점 점수(0~1)를 `create_score`로 남기고 `flush()`할 수 있다
   - 확인: `=== 목표 3 ===` 아래에 `short-answer`와 `llm-judge`가 0.0~1.0 숫자로 나오고, `short-answer` 값이 출력된 답 길이(200자 이하면 1.0)와 맞는다. 코드에서 `langfuse.create_score`가 목표 2의 trace ID를 `trace_id`로 받아 두 이름으로 호출되고, 파일 끝에서 `langfuse.flush()`를 부른다(없으면 ⛔). 조회 결과 목표 2 trace의 점수 목록이 `['llm-judge', 'short-answer']`이면 🟢, 이름이 빠졌으면 ⛔(점수는 늦게 보일 수 있으니 위의 재조회 규칙을 따른다). 출력·코드가 맞는데 조회만 안 되면 ❔
4. LangGraph 그래프에 `CallbackHandler`를 붙여 노드별 실행을 trace로 기록할 수 있다
   - 확인: `=== 목표 4 ===` 아래에 `Tool Message` 칸(`get_weather`, 맑음 23°C)과 마지막 `Ai Message`가 있고, `trace id:` 줄의 값이 목표 1·2의 ID와 다르다(목표 2와 같으면 그래프에 핸들러를 안 붙인 것이다 → ⛔). 코드에서 `compile()` 결과에 `with_config({"callbacks": [...]})`를 붙이거나 `invoke`의 `config`로 핸들러를 넘긴다. 조회 결과 맨 위가 `('LangGraph', '-')`이고 `('agent', 'LangGraph')`와 `('tools', 'LangGraph')`가 있으면 🟢. 출력·코드가 맞는데 조회만 안 되면 ❔

## 확인 질문

목표 2에서 바깥 함수에는 `@observe`를 붙였지만, 그 안의 `chain.invoke`에 `CallbackHandler`를 넘기지 않으면 Langfuse 화면은 어떻게 되나요?

1. 아무 차이 없이 체인의 단계까지 모두 기록된다
2. 바깥·안쪽 함수 span은 남지만, 체인의 프롬프트·모델 호출 단계는 그 trace에 기록되지 않는다
3. 프로그램이 오류를 내고 멈춘다
4. 체인 단계만 기록되고 `@observe` 함수는 기록되지 않는다

정답: 2

해설:
- 1: `@observe`는 그 함수의 호출만 기록합니다. LangChain 체인 안의 단계는 `CallbackHandler`가 있어야 기록됩니다.
- 2: 맞습니다. 함수 span은 `@observe`가, 체인 단계는 `CallbackHandler`가 남깁니다. 둘을 함께 써야 한 trace에 트리로 모입니다.
- 3: 핸들러를 빼도 체인은 정상으로 돌고 답도 나옵니다. 그래서 출력만 보고는 기록이 빠진 줄 모르기 쉽습니다.
- 4: 반대입니다. `@observe`를 붙인 함수는 핸들러와 상관없이 기록됩니다.
