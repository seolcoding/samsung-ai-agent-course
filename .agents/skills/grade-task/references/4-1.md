# 4-1 과제: 회의록 요약 스킬을 쓰는 Deep Agent

- 과제 파일: `course/Chapter02/tasks/4-1/4-1_task.py`, `course/Chapter02/tasks/4-1/skills/meeting-summary/SKILL.md` (두 파일)
- 실행 명령(저장소 맨 위에서): `uv run --env-file .env python course/Chapter02/tasks/4-1/4-1_task.py`
- 시작 상태: `4-1_task.py`에 `✍️ 목표 N` 주석과 "아직 비어 있습니다" 출력이 남아 있거나, SKILL.md의 `description`·본문에 `✍️ 목표 2` 문구가 남아 있다. 이 자리가 하나라도 남아 있으면 그 목표는 아직 하지 않은 것이다.

## 학습 목표와 확인 방법

1. `@tool` 도구와 시스템 프롬프트를 `create_deep_agent`에 묶어 Agent를 만들 수 있다
   - 확인: 코드에 `@tool` 함수 `get_meeting_notes`가 있고, `build_agent(root_dir)`가 `create_deep_agent(model=llm, tools=[get_meeting_notes, …], backend=FilesystemBackend(root_dir=root_dir, virtual_mode=True), skills=…, system_prompt=…, checkpointer=MemorySaver())`를 돌려준다. 실행 출력의 요청 1(`주간 회의 회의록을 가져와서 요약해 줘.`)에 `Name: get_meeting_notes`인 `Tool Message`가 있다
2. 머리말(`name`·`description`)과 양식 본문이 있는 SKILL.md를 쓰고 skills 폴더로 연결해 그 양식대로 답하게 할 수 있다
   - 확인: SKILL.md 맨 위 `---` 사이에 `name: meeting-summary`와 언제 쓰는지 적은 `description`이 있고, 본문에 `[회의 요약]`·`결정 사항`·`할 일(담당자)` 양식이 있다. 코드의 `skills` 값이 SKILL.md가 든 폴더(`skills/meeting-summary/`)가 아니라 그 상위 폴더(`["skills/"]`)다(스킬 폴더를 가리키면 오류 없이 스킬을 0개 찾는다). 요청 1 출력에 `Name: read_file`인 `Tool Message`가 있고 그 안에 `name: meeting-summary`가 보인다. 요청 1의 마지막 `Ai Message` 첫 줄이 `[회의 요약]`이고, `get_meeting_notes` 결과에 나온 담당자 이름이 들어 있다
3. `system_prompt`로 범위 밖 요청을 거절시키고 두 요청의 결과를 비교할 수 있다
   - 확인: 코드의 `system_prompt`에 회의록 요약 밖의 요청을 거절하라는 말이 있고, 요청 2(`파이썬으로 피보나치 코드를 짜 줘.`)를 요청 1과 다른 `thread_id`로 실행한다. 요청 2의 마지막 `Ai Message`에 코드(`def`, 코드 블록)가 없고 거절하는 말이 있다. `=== 요청 1과 요청 2 비교 ===` 아래에 두 요청의 마지막 답이 함께 나온다
4. 코드·모델은 그대로 두고 SKILL.md 한 줄만 바꿔 출력이 달라지는 것을 전후 비교로 보일 수 있다
   - 확인: 출력에 `바꾼 줄(사본 SKILL.md, 원본은 그대로):`과 `-`/`+` 한 쌍이 있다(`copy_skills_with_one_line_changed`가 줄을 하나만 바꿨다). 코드에서 사본 Agent를 같은 `build_agent`에 사본 폴더만 넣어 만든다(모델·도구·`system_prompt`를 따로 바꾸지 않는다). 사본 Agent 실행의 `read_file` `Tool Message`에 새 줄이 보이고, `=== SKILL.md 한 줄 전후 비교 ===` 아래 [바꾼 후] 답이 새 줄대로 달라졌다(예: 첫 줄이 새 머리글). 사본 Agent가 `read_file`로 스킬을 읽지 않고 답했으면 출력이 달라도 ⛔다(스킬 때문이 아니다. `description`을 더 분명히 쓰게 한다). 실행 뒤 `git status`에 과제 폴더 밖 새 파일이 없다

## 확인 질문

목표 4에서 SKILL.md 한 줄만 바꿨는데 같은 코드·같은 모델의 답이 달라졌습니다. 왜 그런가요?

1. 사본 Agent가 다른 모델을 쓰기 때문
2. Agent가 실행할 때마다 SKILL.md를 `read_file`로 읽어 그 내용대로 답하기 때문
3. `system_prompt`가 SKILL.md 내용으로 덮어써지기 때문
4. 모델이 SKILL.md를 미리 학습해 두었기 때문

정답: 2

해설:
- 1: 두 Agent 모두 `build_agent`가 같은 `llm`으로 만듭니다. 바뀐 것은 작업 공간 폴더뿐입니다.
- 2: Agent는 처음에 스킬의 `name`·`description`만 보고, 쓸 스킬이면 `read_file`로 본문을 읽어 따릅니다. 그래서 코드를 고치지 않고 파일만 바꿔도 동작이 바뀝니다.
- 3: `system_prompt`는 그대로입니다. 스킬 목록은 시스템 프롬프트에 덧붙고, 본문은 필요할 때 따로 읽습니다.
- 4: 모델은 SKILL.md를 학습하지 않습니다. 실행 중에 파일을 읽을 뿐이어서, 읽지 않으면 양식을 모릅니다.
