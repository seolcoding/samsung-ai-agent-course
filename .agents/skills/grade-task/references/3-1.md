# 3-1 과제: 약관 검색 도구 Agent

- 과제 파일: `course/Chapter02/tasks/3-1/3-1_task.py`
- 실행 명령(저장소 맨 위에서): `uv run --env-file .env python course/Chapter02/tasks/3-1/3-1_task.py`
- 시작 상태: `✍️ 목표 N은(는) 아직 비어 있습니다` 출력 줄이 4개 모두 남아 있으면 채점하지 않는다. 일부만 남아 있으면 남은 목표는 ⛔로 본다.
- 걸리는 시간: 모델 호출 4~6번과 임베딩으로 15~40초(사외 실측 15초).

## 학습 목표(채점 기준)

1. `config.check`로 설정을 점검하고 ⛔ 항목을 고쳐 모델 호출까지 통과시킬 수 있다
   - 확인: 출력 맨 앞에 점검 결과가 나오고, 그 안에 `🟢 LLM 호출`과 `🟢 임베딩 호출` 줄, 마지막에 `준비 완료`가 있다. 코드에서 `config.check`의 `check_env`를 실제 호출 옵션(`live=True`)과 임베딩(`"EMBED_PROVIDER"`)을 넣어 부르고, 결과가 `False`면 `sys.exit`(또는 `raise SystemExit`)로 멈춘다. 점검이 `get_llm()`보다 앞에 있다. `LLM 호출` 줄이 없거나(`live` 빠짐), 결과를 보지 않고 그냥 넘어가면 ⛔. 키·토큰 값을 `print`하는 코드가 있으면 ⛔.
   - 점검이 ⛔으로 멈췄으면 나머지 기준은 ❔로 두고, ⛔ 줄의 `→` 안내대로 `.env`를 고치게 한다.
2. `get_embeddings()`와 Chroma로 검색기를 만들고 `@tool search_policy`로 감쌀 수 있다
   - 확인: 코드에서 `PDF_PATH`의 PDF를 읽어 청크로 나누고, 맨 위의 `embeddings`(= `get_embeddings()`)로 `Chroma`를 만들어 `as_retriever`(조각 3개 안팎)로 바꾼다. `@tool`이 붙은 `search_policy(query: str)`가 검색기를 불러 찾은 조각의 글을 합쳐 돌려주고, docstring에 약관 검색 도구라는 설명이 있다. 실행 출력의 `Tool Message`에 약관 문장(보험금·보장·수술 등)이 나온다. `OpenAIEmbeddings` 등 다른 임베딩을 직접 쓰거나, 도구가 고정 문자열을 돌려주면 ⛔.
3. `tools_condition`과 `add_edge("tools", "agent")`로 도구를 반복해 호출하는 그래프를 만들 수 있다
   - 확인: 코드에 `StateGraph`, agent 노드(도구를 `bind_tools`로 연결한 LLM 호출, 바뀐 `messages`만 dict로 반환), `ToolNode`로 만든 tools 노드, `add_conditional_edges("agent", tools_condition)`, `add_edge("tools", "agent")`가 있다. 실행 출력에서 약관 질문이 `Tool Message` 다음 `Ai Message`로 끝나고, 그 마지막 답이 바로 위 `Tool Message`의 약관 내용(수술비 보장 여부·조건)과 맞다. 도구를 두 번 이상 부른 뒤 답해도 된다. `Tool Message`로 끝나면 tools → agent 연결이 빠진 것이라 ⛔. `create_react_agent` 같은 미리 만든 Agent로 대신하면 ⛔.
4. 약관 질문에서만 도구를 호출하고 인사에는 호출하지 않는 것을 `pretty_print`로 보여 줄 수 있다
   - 확인: 출력에 `Human Message`/`Ai Message`/`Tool Message` 칸(`=== … ===` 머리줄)이 질문 두 개 모두에 나온다. 약관 질문: `Ai Message`의 Tool Calls에 `search_policy`가 있고 이어서 `Tool Message`가 있다(마지막 답의 내용은 기준 3에서 본다). 인사 질문: `Tool Message`가 없고 `Ai Message` 하나로 끝난다. 코드에서 `policy_agent_result["messages"]`를 꺼내 하나씩 `pretty_print()`한다. 마지막 답만 `print(...content)`로 찍었거나, 인사에도 도구를 불렀으면 ⛔(인사에 도구를 부르면 다음 할 일은 docstring을 분명히 고치게 하는 것).

## 확인 질문

인사 질문에도 Agent가 약관 검색 도구를 불렀습니다. 먼저 고칠 곳은 어디인가요?

1. 청크 크기를 더 작게 바꾼다
2. retriever가 찾는 조각 수를 늘린다
3. 도구 docstring에 펫보험 약관 질문에만 쓰는 도구라고 분명히 적는다
4. 임베딩 모델을 다른 것으로 바꾼다

정답: 3

해설:
- 1: 청크 크기는 검색 단위를 바꿀 뿐, 도구를 부를지 말지에는 영향이 없습니다.
- 2: 조각 수는 도구를 부른 뒤의 검색 결과 양입니다. 부를지 말지는 바뀌지 않습니다.
- 3: 모델은 docstring(도구 설명)을 보고 도구를 고릅니다. 언제 쓰는 도구인지 분명하면 관계없는 질문에는 부르지 않습니다.
- 4: 임베딩은 검색 품질에 관여합니다. 도구를 고르는 판단은 모델이 도구 설명을 보고 합니다.
