# 3-1 과제: 약관 검색 도구를 쓰는 Agent

빌드 산출물이다(dev/builders/build_lab.py). 직접 고치지 않는다.

- 과제 파일: `course/Chapter02/notebooks/3-1_task.py`
- 실행 명령(저장소 맨 위에서): `uv run --env-file .env python course/Chapter02/notebooks/3-1_task.py`

## 목표

약관 PDF 검색을 도구로 만들어 LangGraph Agent에 연결합니다. Agent는 약관 질문에는 검색 도구를 불러 그 결과로 답하고, 약관과 관계없는 말에는 도구 없이 답합니다. 도구 호출(3장), 그래프(4장), RAG(5장)를 한 프로그램에 모읍니다.

## 들어갈 것

- `data` 폴더의 약관 PDF를 읽어 청크로 나누고, `get_embeddings()`로 Chroma 벡터 저장소를 만들어 retriever(조각 3개)로 바꿉니다
- `@tool`로 약관 검색 도구 `search_policy(query: str)`를 만듭니다. retriever가 찾은 조각을 합친 글을 돌려주고, docstring에 "펫보험 약관에서 질문과 관련된 내용을 찾는다"처럼 언제 쓰는 도구인지 적습니다
- State는 `messages` 하나이고, agent 노드는 도구가 연결된 LLM을 호출합니다. agent → (`tools_condition`) → tools → agent로 잇습니다
- 질문 "반려동물 수술비도 보장되나요?"와 "안녕하세요, 자기소개를 한 줄로 해 주세요"를 차례로 실행하고, 결과는 `results = policy_agent_result["messages"]`처럼 꺼내 `for m in results: m.pretty_print()`로 출력합니다

## 성공 기준과 확인 방법

1. 🟢 약관 질문에는 `search_policy` 도구 호출과 `Tool Message` 칸이 나온다
   - 확인: 첫 질문 출력의 `Ai Message`에 `search_policy` 도구 호출(Tool Calls)이 있고, 이어서 약관 문장이 든 `Tool Message` 칸이 있다
2. 🟢 약관 질문의 마지막 답이 검색된 약관 내용을 근거로 한다
   - 확인: 첫 질문의 출력이 `Tool Message` 뒤 `Ai Message`로 끝나고, 그 답이 바로 위 `Tool Message`의 약관 내용(수술비 보장 여부·조건)과 맞다. `Tool Message`로 끝나거나 도구 결과와 상관없는 일반론이면 ⛔. 코드에 tools에서 agent로 돌아가는 `add_edge("tools", "agent")`가 있다
3. 🟢 인사 질문에는 도구를 부르지 않고 바로 답한다
   - 확인: 두 번째 질문 출력에 `Tool Message` 칸이 없고 `Ai Message` 하나로 끝난다. 코드에 agent 뒤 `tools_condition` 갈림길(`add_conditional_edges`)이 있다

## 확인 질문

인사 질문에도 Agent가 약관 검색 도구를 불렀습니다. 먼저 고칠 곳은 어디인가요?

1. 청크 크기를 더 작게 바꾼다
2. retriever가 찾는 조각 수를 늘린다
3. 도구 docstring에 펫보험 약관 질문에만 쓰는 도구라고 분명히 적는다
4. 임베딩 모델을 다른 것으로 바꾼다

정답: 3

해설:
- 1: 청크 크기는 검색 단위를 바꿀 뿐, 도구를 부를지 말지에는 영향이 없습니다.
- 2: 조각 수는 도구를 부른 뒤의 검색 결과 양입니다. 부를지 말지는 바뀌지 않습니다.
- 3: 모델은 docstring(도구 설명)을 보고 도구를 고릅니다. 언제 쓰는 도구인지 분명하면 관계없는 질문에는 부르지 않습니다.
- 4: 임베딩은 검색 품질에 관여합니다. 도구를 고르는 판단은 모델이 도구 설명을 보고 합니다.
