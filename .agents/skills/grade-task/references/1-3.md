# 1-3 과제: 회의 메모 정리 체인

빌드 산출물이다(dev/builders/build_lab.py). 직접 고치지 않는다.

- 과제 파일: `course/Chapter01/notebooks/1-3_task.py`
- 실행 명령(저장소 맨 위에서): `uv run --env-file .env python course/Chapter01/notebooks/1-3_task.py`

## 목표

회의 메모를 받아 제목·결정 사항·할 일로 정리하는 LCEL 체인을 만듭니다. 결과는 Pydantic 스키마로 받고, 회의 메모 두 개를 한 번에(`batch`) 처리합니다.

## 들어갈 것

- `MeetingNote` 스키마(제목 `title`, 결정 사항 목록 `decisions`, 할 일 목록 `todos`)를 Pydantic으로 만듭니다
- `PydanticOutputParser`와 `format_instructions`를 넣은 프롬프트를 만듭니다
- `prompt | llm | parser`로 체인을 잇습니다
- 짧은 회의 메모 두 개를 `batch()`로 한 번에 처리하고, 메모마다 세 항목을 출력합니다

## 성공 기준과 확인 방법

1. 🟢 두 메모 모두 제목·결정 사항·할 일이 출력된다
   - 확인: 출력에 메모 두 개분의 제목, 결정 사항, 할 일이 있다
2. 🟢 결과를 속성(`.title`, `.decisions`, `.todos`)으로 꺼내 출력한다
   - 확인: 코드가 결과 객체의 속성으로 값을 꺼낸다(문자열을 잘라 쓰지 않는다)
3. 🟢 체인이 `|`로 이어져 있고 `batch()`로 두 메모를 한 번에 실행한다
   - 확인: 코드에 `prompt | llm | parser` 모양과 `.batch(`가 있다

## 확인 질문

프롬프트에 `format_instructions`를 넣는 이유는 무엇인가요?

1. 체인을 더 빨리 실행하려고
2. 모델이 스키마에 맞는 모양으로 답하도록 형식을 알려 주려고
3. 모델이 앞 대화를 기억하게 하려고
4. 답을 조각으로 나눠 받으려고

정답: 2

해설:
- 1: 실행 속도와는 관계가 없습니다.
- 2: 파서가 읽을 수 있는 형식을 모델에게 알려 줘야 결과를 스키마로 바꿀 수 있습니다.
- 3: 대화 기억은 메시지 기록을 넣어 주는 일입니다.
- 4: 조각으로 받는 것은 `stream()`입니다.
