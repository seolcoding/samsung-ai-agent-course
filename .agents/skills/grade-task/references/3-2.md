# 3-2 과제: 서버를 직접 띄우는 stdio MCP Agent

빌드 산출물이다(dev/builders/build_lab.py). 직접 고치지 않는다.

- 과제 파일: `course/Chapter02/notebooks/3-2_task.py`
- 실행 명령(저장소 맨 위에서): `uv run --env-file .env python course/Chapter02/notebooks/3-2_task.py`

## 목표

용어 사전 도구를 가진 FastMCP 서버와, 그 서버를 stdio로 연결해 쓰는 LangGraph Agent를 한 파일에 만듭니다. 클라이언트가 이 파일을 서버로 직접 실행하므로 서버 터미널을 따로 켜지 않고 명령 한 번으로 끝까지 실행됩니다.

## 들어갈 것

- FastMCP 서버에 `@mcp.tool()`로 용어 사전 도구(MCP·RAG·LangGraph 세 용어의 뜻을 담은 고정 사전에서 찾기)와 글자 수 세기 도구(공백 포함)를 등록합니다
- 파일 맨 아래에서 `--server`를 붙여 실행되면 `mcp.run(transport="stdio")`로 서버만 돌고, 아니면 `asyncio.run(main())`으로 클라이언트가 돌게 나눕니다
- `main()`에서 `MultiServerMCPClient`에 stdio 설정(`"command": sys.executable`, `"args": [__file__, "--server"]`)을 주고, `await client.get_tools()`로 받은 도구의 이름과 설명을 출력합니다
- 받은 도구로 agent → (`tools_condition`) → tools → agent 그래프를 만들고 `"MCP가 무슨 뜻이야? 사전에서 찾아 줘."`와 `"'에이전트 개발 교육'은 몇 글자야?"`를 `await app.ainvoke(...)`로 실행합니다
- 결과는 `results = mcp_graph_result["messages"]`처럼 꺼내 `for m in results: m.pretty_print()`로 출력합니다

## 성공 기준과 확인 방법

1. 🟢 서버 터미널을 따로 켜지 않아도 명령 한 번으로 실행이 끝까지 돌고 스스로 끝난다
   - 확인: 실행 명령 하나로 오류 없이 끝난다. 코드에 `"transport": "stdio"`와 `args`에 이 파일(`__file__`)과 `--server`가 있고, `--server`일 때 `mcp.run(transport="stdio")`를 부른다(SSE·포트 설정 없음)
2. 🟢 `=== 사용 가능한 MCP 도구 ===` 아래에 사전 찾기 도구와 글자 수 세기 도구가 이름과 설명으로 나온다
   - 확인: 출력의 도구 목록에 도구 2개가 함수 설명과 함께 나온다. 코드에서 두 도구가 모두 서버의 `@mcp.tool()`로 등록되어 있고, LangChain `@tool`로 만든 도구를 `get_tools()` 결과에 덧붙이지 않았다(덧붙이면 목록에는 보여도 MCP를 거치지 않는다)
3. 🟢 두 질문 모두 `Tool Message` 칸이 나오고, 마지막 `Ai Message`가 그 도구 결과(사전의 뜻, 센 글자 수)로 답한다
   - 확인: 질문마다 `Tool Message` 칸이 있다. MCP 질문의 마지막 `Ai Message`에 사전의 뜻(Model Context Protocol)이 있고, 글자 수 질문의 마지막 `Ai Message`에 바로 위 `Tool Message`의 숫자가 있다. 모델이 따옴표까지 넘겨 도구가 12를 돌려주고 답에서 따옴표를 뺀 10으로 말해도 도구 결과를 쓴 것으로 본다(공백 포함 정답은 10)

## 확인 질문

이 과제에서는 서버 터미널을 따로 켜지 않았는데도 도구가 동작했습니다. 왜 그런가요?

1. LLM이 도구 함수를 직접 실행하기 때문
2. 도구가 Agent 코드 안에 `@tool`로 들어 있기 때문
3. stdio 방식이라 클라이언트가 이 파일을 `--server`로 직접 실행해 표준 입출력으로 주고받기 때문
4. FastMCP가 8000번 포트에 SSE 서버를 저절로 띄우기 때문

정답: 3

해설:
- 1: LLM은 도구 호출을 요청할 뿐이고, 실행은 서버가 합니다.
- 2: 도구는 `@mcp.tool()`로 서버에 등록했습니다. Agent는 `get_tools()`로 가져다 씁니다.
- 3: stdio에서는 Host(클라이언트)가 서버 프로그램을 하위 프로세스로 띄우고 끝나면 정리합니다. 그래서 명령 한 번으로 끝납니다.
- 4: SSE는 서버를 먼저 따로 켜 두어야 하는 방식입니다. 이 과제는 포트를 쓰지 않습니다.
