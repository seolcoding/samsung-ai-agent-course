# 3-2 과제: MCP 서버를 직접 띄우는 Agent

- 과제 파일: `course/Chapter02/tasks/3-2/3-2_task.py`
- 실행 명령(저장소 맨 위에서): `uv run --env-file .env python course/Chapter02/tasks/3-2/3-2_task.py`
- 이 파일 하나가 서버이자 클라이언트다. 클라이언트가 이 파일을 `--server`로 띄워 stdio로 연결하므로 서버 터미널을 따로 켜지 않는다. 명령 한 번으로 끝까지 돌고 스스로 끝나야 한다(10~30초).
- 시작 상태: `# ✍️ 목표 N` 주석 아래가 비어 있고, 실행하면 `(아직 없습니다. 목표 2를 작성합니다)`, `(목표 3을 아직 작성하지 않았습니다)`, `(목표 4를 아직 작성하지 않았습니다)`가 나온다. 이 문구가 남아 있으면 그 목표는 아직 하지 않은 것이다.

## 학습 목표와 확인 방법

1. 🟢 FastMCP `@mcp.tool()`로 함수 2개를 MCP 도구로 등록할 수 있다
   - 확인: 코드에서 서버(`mcp = FastMCP(...)`) 쪽에 `@mcp.tool()`이 붙은 함수가 2개 있다. 하나는 `GLOSSARY`에서 용어의 뜻을 찾고, 하나는 공백을 포함해 글자 수를 센다(`len(text)`). 함수마다 설명(docstring)이 있다. LangChain `@tool`로 만든 도구는 MCP 도구가 아니다
2. 🟢 `MultiServerMCPClient`를 stdio로 연결해 `get_tools()`로 도구 목록을 받을 수 있다
   - 확인: 출력의 `=== 사용 가능한 MCP 도구 ===` 아래에 목표 1의 도구 2개가 이름과 설명으로 나오고, Resource·Prompt 이름은 도구 목록에 없다. 코드의 연결 설정에 `"transport": "stdio"`가 있고 `args`에 이 파일(`__file__`)과 `--server`가 있다(`command`는 `sys.executable`. `"python"`이어도 실행되면 통과). `url`·포트·SSE 설정이 없다. `get_tools()` 결과에 LangChain `@tool` 도구를 덧붙이지 않았다(덧붙이면 목록에는 보여도 MCP를 거치지 않는다)
3. 🟢 받은 MCP 도구를 LangGraph Agent에 붙여 질문에 도구로 답하게 할 수 있다
   - 확인: 두 질문(`MCP가 무슨 뜻이야? 사전에서 찾아 줘.`, `'에이전트 개발 교육'은 몇 글자야?`)마다 `Tool Message` 칸이 나오고 `Name:`이 목표 1의 도구다. MCP 질문의 마지막 `Ai Message`에 사전의 뜻(Model Context Protocol)이 있고, 글자 수 질문의 마지막 `Ai Message`에 바로 위 `Tool Message`의 숫자가 있다(공백 포함 정답은 10. 모델이 따옴표까지 넘겨 12가 나와도 도구 결과를 그대로 쓰면 통과). 코드에 `bind_tools(tools)`, `ToolNode(tools)`, `tools_condition`으로 agent → tools → agent 그래프가 있고, 결과를 `results = …_result["messages"]`로 꺼내 `pretty_print()`한다. 메시지 칸 없이 마지막 답만 찍으면 도구 호출을 볼 수 없으니 ⛔
4. 🟢 `@mcp.resource()`와 `@mcp.prompt()`를 정의하고 읽어 올 수 있다
   - 확인: 코드의 서버 쪽에 `@mcp.resource("glossary://terms")`(사전의 용어 목록)와 `@mcp.prompt()`(용어를 받아 질문을 만드는 함수)가 있다. 출력의 `=== Resource ===` 아래에 사전 용어(MCP, RAG, LangGraph)가, `=== Prompt ===` 아래에 `RAG`가 들어간 질문 문장이 나온다. 클라이언트에서 같은 client로 `get_resources(...)`와 `get_prompt(..., arguments={"term": "RAG"})`로 읽거나, `client.session(...)`으로 `read_resource`·`get_prompt`를 불러 읽어도 통과다. 서버 함수를 클라이언트에서 직접 불러 출력했으면(MCP를 거치지 않음) ⛔

## 확인 질문

이 과제에서는 서버 터미널을 따로 켜지 않았는데도 도구가 동작했습니다. 왜 그런가요?

1. LLM이 도구 함수를 직접 실행하기 때문
2. 도구가 Agent 코드 안에 `@tool`로 들어 있기 때문
3. stdio 방식이라 클라이언트가 이 파일을 `--server`로 직접 실행해 표준 입출력으로 주고받기 때문
4. FastMCP가 8000번 포트에 SSE 서버를 저절로 띄우기 때문

정답: 3

해설:
- 1: LLM은 도구 호출을 요청할 뿐이고, 실행은 서버가 합니다.
- 2: 도구는 `@mcp.tool()`로 서버에 등록했습니다. Agent는 `get_tools()`로 가져다 씁니다.
- 3: stdio에서는 Host(클라이언트)가 서버 프로그램을 하위 프로세스로 띄우고 끝나면 정리합니다. 그래서 명령 한 번으로 끝납니다. 이때 서버의 표준 출력이 통신 통로라서 서버 쪽에서 `print()`한 글자는 화면에 나오지 않습니다.
- 4: SSE는 서버를 먼저 따로 켜 두어야 하는 방식입니다. 이 과제는 포트를 쓰지 않습니다.
