# 1-4 과제: 약관 질문 RAG

빌드 산출물이다(dev/builders/build_lab.py). 직접 고치지 않는다.

- 과제 파일: `course/Chapter01/notebooks/1-4_task.py`
- 실행 명령(저장소 맨 위에서): `uv run --env-file .env python course/Chapter01/notebooks/1-4_task.py`

## 목표

실습에서 쓴 보험 약관 PDF로 질문 두 개에 답하는 RAG 스크립트를 만듭니다. 질문마다 검색된 조각의 쪽 번호를 함께 보여 주고, 약관에 없는 내용은 모른다고 답하게 합니다.

## 들어갈 것

- `data` 폴더의 약관 PDF를 쪽마다 읽고(`PDFMinerLoader(..., mode="page")`, 쪽 번호가 메타데이터에 들어갑니다) 청크로 나눕니다
- `get_embeddings()`로 Chroma 벡터 저장소를 만들고 retriever(조각 3개)로 바꿉니다
- "맥락에 없으면 모른다고 답한다"는 지시가 든 프롬프트로 RAG 체인을 만듭니다
- 질문 "반려동물 수술비도 보장되나요?"(약관에 있음)와 "자동차 보험료는 얼마인가요?"(약관에 없음)를 실행하고, 질문마다 검색된 조각의 쪽 번호와 답을 출력합니다

## 성공 기준과 확인 방법

1. 🟢 질문마다 검색된 조각의 쪽 번호가 출력된다
   - 확인: 출력에 질문마다 쪽 번호(`page` 메타데이터) 3개 안팎이 있다. 쪽 번호가 `None`이면 ⛔
2. 🟢 약관에 있는 질문에는 약관 내용으로 답한다
   - 확인: 첫 질문의 답이 검색된 약관 내용과 맞다
3. 🟢 약관에 없는 질문에는 모른다고 답한다
   - 확인: 두 번째 질문의 답이 지어내지 않고 약관에 없다고 말한다

## 확인 질문

약관에 없는 질문에 모델이 그럴듯한 답을 지어냈습니다. 먼저 고칠 곳은 어디인가요?

1. 청크 크기를 아주 크게 바꾼다
2. temperature를 높인다
3. 프롬프트에 "맥락에 없으면 모른다고 답한다"는 지시를 넣는다
4. 임베딩 모델을 빼고 질문만 보낸다

정답: 3

해설:
- 1: 청크 크기는 검색 단위를 바꿀 뿐, 지어내는 버릇을 막지 않습니다.
- 2: temperature를 높이면 답이 더 다양해져 지어낼 가능성이 커집니다.
- 3: 모델이 맥락 밖의 답을 하지 않도록 프롬프트에서 규칙을 정해 줍니다.
- 4: 검색을 빼면 근거가 없어져 더 지어내게 됩니다.
