- 과제 파일: `course/Chapter01/chatbot/stage5.py` (화면은 `course/Chapter01/chatbot/ui.py`, 고치지 않는 파일. 이 단계에서 읽기만 한다)
- 확인 명령(저장소 맨 위에서, 화면 없이): `uv run --env-file .env python .agents/skills/grade-task/scripts/check_streamlit.py course/Chapter01/chatbot/stage5.py --stage 5`
  - 사이드바를 건드리지 않고(처음 값 그대로) ① "안녕! 내 이름은 민수야." ② "반려견이 수술을 받으면 수술비도 보장되나요?" ③ "내 이름이 뭐야?" ④ "1234 곱하기 5678은 얼마야?"를 차례로 보낸다. 💬는 채팅 메시지, 📂는 실행 기록 상자, `[노드 순서] …`·`[도구 결과] …`는 앱이 터미널에 남긴 기록이다. 1분쯤 걸릴 수 있다.
  - 출력에 약관 PDF 글이 섞여 `grep`이 바이너리로 볼 수 있다. 출력을 거르지 말고 그대로 읽는다.
- 시작 상태: `answer`가 "답 방식"(`mode`)에 따라 갈라지고 사이드바에 "답 방식" 선택 상자가 있다. 그대로면 채점하지 않는다.

## 학습 목표와 확인 방법

1. 일반 질문·약관 질문·기억 질문이 한 화면에서 모두 동작하는 최종 챗봇을 완성할 수 있다
   - 확인: 코드의 `answer`가 선택 상자 값과 관계없이 에이전트 그래프로 답하고(`agent_answer`), 에이전트 도구에 `search_policy`와 `calculate`가 있다. 확인 명령에서 네 질문이 모두 이렇게 되어야 🟢다.
     - ① 일반: `[노드 순서] agent`, 답이 인사에 답한다
     - ② 약관: `[노드 순서]`에 `tools`가 있고 `[도구 결과]`에 약관 글이 있으며, 답이 그 내용(수술, 입원의료비, 보상한도 등)으로 답한다
     - ③ 기억: `[노드 순서] agent`, 답에 "민수"가 있다
     - ④ 계산: `[도구 결과] 7006652`가 있고 답에 7006652(쉼표가 있어도 됨)가 있다
   - 하나라도 어긋나면 ⛔이고 어느 질문인지 적는다. `[노드 순서]` 기록이 없고 일반 답만 나오면 아직 "대화" 방식으로 답하는 것이다(⛔, 시작 상태와 같음). 약관 질문에 도구 없이 일반 지식으로 답하면 ⛔. 사이드바의 "답 방식" 선택 상자가 남아 있어도 네 질문이 모두 맞으면 🟢로 보되, 지우라고 다음 할 일에 적는다

## 확인 질문

`ui.py`에서 대화 기록을 보통 변수(`messages = []`)가 아니라 `st.session_state.messages`에 두는 까닭은 무엇인가요?

1. Streamlit은 입력이 있을 때마다 파일을 위에서부터 다시 실행하므로, 보통 변수는 매번 빈 목록으로 돌아가기 때문
2. `st.session_state`에 두면 모델이 대화를 자동으로 기억하기 때문
3. 보통 변수에는 한글을 넣을 수 없기 때문
4. `st.chat_input`이 `st.session_state`에서만 질문을 읽기 때문

정답: 1

해설:
- 1: 질문을 보낼 때마다 스크립트 전체가 다시 실행됩니다. `st.session_state`는 다시 실행해도 같은 브라우저 탭 동안 값이 남아서 지난 대화를 다시 그릴 수 있습니다.
- 2: `st.session_state`는 화면을 위한 저장소입니다. 모델의 기억은 메시지를 다시 보내거나(2단계) 그래프 checkpointer(4단계)로 만듭니다.
- 3: 보통 변수에도 한글을 넣을 수 있습니다. 다시 실행될 때 사라지는 것이 문제입니다.
- 4: `st.chat_input`은 입력한 글을 바로 돌려줍니다. 그 글을 기록에 더하는 것은 `ui.py`의 `add_message`입니다.
